# 概要

Query Fields では取得しづらい項目（採番規則のある見積番号、適格請求書発行事業者登録番号 T コード等）を補うため、文書種別設定に正規表現パターンを持たせ、IDP 実行時に DI 全文テキストへ適用した結果を保存・返却する。

## 関連Issue

Closes #107

## 変更内容

- `document_type_configs.patterns`（`{key, label, regex}` 配列）を追加。設定 API で登録・取得でき、`regex` は `re.compile` 検証と 512 文字上限。PUT は全置換（省略時 `[]`）
- `AnalysisResult` に DI 応答 `content`（全文テキスト）を追加
- IDP 実行時に `re.finditer` で全一致を集め、実行時点の `label` / `regex` と一緒に `idp_runs.pattern_matches` へ保存して応答に含める（出現順・重複あり、長さ 0 の一致は除外。失敗時 null）
- 既存シード 2 種別に `TCode`（`T\d{13}`）を投入
- Viewer は未変更（`schema.d.ts` 再生成のみ）
- `docs/data-model/document-type-configs.md` / `idp-runs.md` を更新

## 動作確認方法

1. `cd api && uv run pytest` が全件通過する
2. `PUT /api/v1/config/document-types/quotation` に `patterns: [{"key":"TCode","label":"登録番号","regex":"T\\d{13}"}]` を含めて 200、`regex: "("` で 422
3. T コードを含む PDF で `POST /api/v1/documents/{id}/idp-runs` を実行し、応答 `pattern_matches.TCode.values` に出現順で並ぶ
4. `GET /api/v1/documents/{id}/idp-runs` の履歴に同じ `pattern_matches` が残る

## 備考

- 正規表現はテナント管理者入力で、Python `re` にはタイムアウトがない（ReDoS）。PoC では長さ上限とコンパイル検証のみ。本番前に `re2` 等への差し替えを検討する（コードに `ponytail:` コメントで明記）
- `patterns` の PUT は全置換。旧形式の body（`patterns` なし）で PUT すると `[]` になる
