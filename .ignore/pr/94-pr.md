# 概要

閲覧用URL経由でページ画像が表示されるたびに、ページ番号付きの `page_view` イベントを記録し、外部連携フィードで提供する。取引先が何ページ目まで確認したかを把握できるようにする。

## 関連Issue

Closes #93

## 変更内容

- `view_events` に `page` 列（integer NULL）と種別 `page_view` を追加（マイグレーション `d4c8e2a7f513`、CHECK `(event_type = 'page_view') = (page IS NOT NULL)`）
- `GET /view/{token}/pages/{page}/image` の配信成功時に `page_view` をページ番号付きで記録（応答に `Cache-Control: no-store` を付与）
- `/api/view-events`・`/api/documents/{id}/events` の応答に `page` 項目を追加（`view` / `download` は null）し、OpenAPI・TS型を再生成
- Viewer `PageSvg` を IntersectionObserver による遅延読込に変更（表示領域に入ったページだけ画像取得＝ページ表示）。`IntersectionObserver` 未定義時は即時取得
- `_record_event` の IntegrityError 握り潰しに warning ログを追加
- `docs/data-model/view-events.md`・`docs/requirements/viewer.md`・`docs/viewer/display.md` を更新し、ADR-0015 を追加

## 動作確認方法

1. `podman compose up -d` でスタックを起動し、`cd api && uv run alembic upgrade head` を実行する
2. 見積文書を登録して閲覧用URLを発行し、`/view/{token}` をブラウザで開く
3. 1ページ目だけ表示した状態で `GET /api/view-events` を呼び、`view` 1件と `page_view`（`page: 1`）1件のみ返ることを確認する
4. 末尾までスクロールし、`page_view` がページ数分に増えることを確認する

## 備考

- **連携側（Power Automate / DataDelivery）の受け入れ確認がリリースの先行条件。** フィードは `page_view` を無条件に返すため、連携側が未知の `event_type=page_view` と `page` 項目を扱えることを確認してからデプロイする。行数は「文書あたり1件」から「表示ページ数に比例」へ増える（ADR-0015「影響」参照）
- 冪等キー `UNIQUE(document_id, occurred_at, event_type)` は変更なし。同一文書・同一マイクロ秒の `page_view` 衝突は挿入スキップ（ADR-0015で受容）
