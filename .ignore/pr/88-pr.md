# 概要

`?document_id=` 付きでViewerにアクセスした際、ログイン後にパラメータが失われ書類ID入力欄が表示される問題を修正する。

## 関連Issue

Closes #87

## 変更内容

- `viewer/src/stores/auth.ts`: `login()` で `signinRedirect` の `state` にログイン前URL（`pathname + search`）を保存。`handleCallback()` が認証済フラグを立てる**前に**復元先URLへ `replaceState` する（同一オリジンの相対パスのみ許可、`//` 始まり・外部URL・未設定は `/` へフォールバック）。フラグ確定後だとDocumentViewが先にマウントされ `/callback?...` を読んでしまうため、順序が重要
- `viewer/src/App.vue`: `/` 固定の `replaceState` を削除（復元はストア側へ移動）。DocumentViewはマウント時に `location.search` を読むため既存ロジックで自動ロードされる
- テスト追加: state保存、復元、不正state時フォールバック、コールバック後にDocumentViewが `document_id` を受け取ること（実ストア＋oidcモック）

セッション永続化・サイレント認証はスコープ外（トークンのメモリ保持方針は維持。ログインボタン押下は引き続き必要）。

4. `/callback` に不正な `state`（返却先が外部URL）で戻った場合は `/` へ遷移すること（単体テストで担保）
