# 概要

「認証付き骨格が動く」状態を確立する。ViewerのKeycloakログイン（OIDC/PKCE）、APIのJWT検証、realm定義の拡充。

Closes #17

## 変更内容

- **realm拡充**（`keycloak/realm/factone.json`）: publicクライアント `factone-viewer`（PKCE S256必須・redirect URI `http://localhost:5173/*`）、audienceマッパー（アクセストークンへ `factone-api` 付与）、テストユーザー `testuser`
- **テストユーザーのパスワード**: Keycloakのrealmインポートは環境変数置換を行わない（`${env.VAR}` がリテラルのままパスワード化することを実機で確認）ため、プレースホルダ方式を廃し `scripts/local-stack/set-test-user-password.sh`（kcadm）で起動後設定する方式に変更
- **API**: PyJWT導入。`app/auth.py` にBearer検証依存性（署名・issuer・audience・exp検証、`alg=none`拒否）。JWKS取得は境界アダプタ（`KeySource`）でテスト時差替え可能。保護エンドポイント `GET /api/me` 追加（`/health` は非保護維持）
- **APIテスト8件**: 正常系+トークンなし・期限切れ・issuer不一致・aud不一致・別鍵署名（偽造）・無署名の異常系、`/health` 非保護確認
- **Viewer**: oidc-client-ts導入。Pinia認証ストア（ログイン/コールバック/ログアウト、トークンはメモリ保持）、openapi-fetchクライアントへBearer自動付与、最小ログインUI。ストアのVitestテスト4件
- **Vite devプロキシ**: `/api` → `localhost:8000`（本番のContainer Apps同居配信と同じ同一オリジン構成）
- **ADR-0001**: 認証トークン処理ライブラリ選定（PyJWT・oidc-client-ts。代替案と却下理由を記録)
- `docs/develop-guide/auth.md` 新規作成・README一覧更新・`keycloak/README.md` 更新・`.env.example` 拡充
