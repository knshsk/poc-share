# 概要

文書IDからPDFをViewerで表示できるようにする（ページ画像のオンデマンド変換・APIプロキシ配信・SVGオーバーレイの器・原本DL）。

## 関連Issue

Closes #21

## 変更内容

API（すべてJWT必須。存在しない文書ID・テナント不一致は404で存在を秘匿）:

- `GET /api/documents/{document_id}` — メタデータ
- `GET /api/documents/{document_id}/pages` — ページ数+各ページ寸法（**インチ単位**。DI座標系とSVG viewBoxの無変換整合用）
- `GET /api/documents/{document_id}/pages/{page}/image` — pypdfium2によるオンデマンドPNG変換（150dpi）。URLに拡張子を含めない（形式はContent-Typeが正）
- `GET /api/documents/{document_id}/pdf` — 原本PDF配信（Content-Disposition付き）
- PDF処理は `PdfRenderer` アダプタとして分離。破損PDFは500+明示detail
- `BlobStorage` へ `load` を追加（Azure/ローカルFS/テストフェイク）

Viewer:

- `DocumentView` — URLクエリ `?document_id=` 受領（案件ID・ルートIDは要求しない）、ページ一覧表示、原本DL（fetch+blob URL）
- `PageSvg` — `viewBox="0 0 {幅in} {高さin}"`、画像はBearer付きfetch+blob URL。読取矩形rectはprops受けの器（DI連携後にデータ供給）

テスト:

- API 8件追加（座標系変換ポイント→インチ、範囲外ページ、破損PDF=fixtures初活用、未認証、404系）
- Viewer 2件追加（viewBox整合・rect無変換描画）
- 共有フィクスチャを `tests/conftest.py` へ集約

ドキュメント:

- `docs/viewer/display.md` 新規（座標系整合・エンドポイント仕様・実装ノート）
