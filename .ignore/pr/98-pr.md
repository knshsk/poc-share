# 概要

APIの全エラー応答をRFC 9457 Problem Details（`application/problem+json`、`type=/errors/<code>`）に統一し、OpenAPIに全4xx/5xxを明記する。

## 関連Issue

Closes #97

## 変更内容

- `api/app/core/problem.py` を新設（`Problem` モデル、`ProblemException`、例外ハンドラ3本、OpenAPI用ヘルパ）
- 既存の `raise HTTPException(...)` 26箇所を発生箇所ごとの固有コード付き `ProblemException` へ置換（`detail` 文言は現行維持）
- ルータ／ルートの `responses=` で全エラー応答を `Problem` スキーマとしてOpenAPIに明記。FastAPI既定の `HTTPValidationError` は契約から消える
- `docs/api/openapi.json` / `viewer/src/api/schema.d.ts` を再生成
- ADR-0016 と `docs/api/README.md` のエラー応答節（コード一覧）を追加
- 異常系テスト `api/tests/test_problem.py`（11件）を追加

## 備考

- Viewer はエラー本文を参照していないため実装変更なし（型再生成のみ）
- `Content-Type` が `application/json` から `application/problem+json` に変わるため、メディアタイプを厳密判定するクライアントは追随が必要
- 422 の `errors` は `loc/msg/type` のみで、FastAPI 既定応答にあった `input`（送信値の反響）は返さなくなる
