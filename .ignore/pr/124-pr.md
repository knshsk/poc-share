# 概要

右ペインを読取結果の確認・修正の作業領域にする。

読取結果タブを「キー項目 / キー項目候補 / グリッド」の 3 区分で表示し、キー項目とグリッドセルをテキストボックスで修正して確定（`POST …/corrections`、#115）できるようにする。未保存の変更は差分のみを Pinia ストアに持ち、履歴選択 / IDP実行 / 文書切替 / ブラウザ離脱をガード。API 変更なし。相互ハイライト（キャンバス⇄右ペイン）は #118 で追加。

## 関連Issue

Closes #117

## 変更内容

- 新規 `components/ResultEditor.vue`: `v-expansion-panels`（初期全展開）で 3 区分を表示
  - キー項目: ラベル（`field_labels`、無ければキー）+ 確信度 % + 編集可テキストボックス（`raw_fields` の文字列。null は空欄・プレースホルダ「（値なし）」）+ 確信度バー。表示順は `raw_fields` のキー順、`visible=false` は非表示。number / date は入力中に「正規化値 …」/「数値として解釈できません」/「日付として解釈できません」を行内表示（送信は妨げない）
  - キー項目候補: パターンごとにラベルと一致値チップ、0 件は「一致なし」（読取専用）
  - グリッド: 「表 n（r 行 × c 列）」+ CSS グリッド。全セル編集可、`columnHeader` は背景色で区別、無い座標は破線の空枠、横は区分内スクロール
  - 修正済み（保存済み `corrections` と下書き）は左端の primary アクセント + 鉛筆アイコン。入力欄に `aria-label`
- 新規 `stores/draft.ts`: 差分のみ保持（`fields` / `cells`）、元値復帰で差分から外す、空欄は null。`guard` / `proceed` / `cancel` で未保存時の操作を保留
- `components/WorkPanel.vue`: 選択中結果のチップ（区分 · 日時 · 修正者、`corrected` は primary）、下部固定アクションバー「変更 N件」+ 破棄 + 確定（N ≥ 1 のみ有効）、確定で差分を POST → 応答の修正行を選択・履歴先頭へ追加・スナックバー「修正を保存しました」（失敗時「修正の保存に失敗しました」、下書き保持）、確認ダイアログ「未保存の変更を破棄しますか？」、`beforeunload` 警告、履歴の区分「初回 / 再実行 / 修正」と修正者表示。パネル内スクロール化（`DocumentView` の `.work-pane` を `overflow: hidden` に）
- `components/AppHeader.vue`: 文書 ID 変更を `draft.guard` 経由に
- `stores/document.ts`: `hiddenFieldKeys` を `fieldDefs`（key / label / type / visible）に置き換え
- 新規 `utils/normalize.ts`（サーバ `_normalize` と同規則のクライアント側ヒント）、`utils/runs.ts`（`tables` / `pattern_matches` / `corrections` の型付けと区分ラベル）
- #114 持ち越し: IDP実行 / 確定の応答受信時に `pendingRunId` を更新し、遅れて届いた詳細応答で表示を上書きしない
- 通信障害（fetch の reject）でも各操作のエラーメッセージを表示。一覧取得中に IDP実行が完了した場合は一覧応答で選択を上書きしない。パネルのアンマウントで保留中のガード操作を取り消す
- テスト: normalize 単体、draft ストア、ResultEditor（3 区分・除外・件数増減・ヒント・修正済みマーク・空枠）、WorkPanel（確定 POST・応答選択・履歴追加・アクションバー活性・確認ダイアログ・beforeunload・持ち越し回帰）、AppHeader ガード
- ドキュメント: 新規 `docs/viewer/result-panel.md`、`viewer/README.md`

## 動作確認方法

1. `podman compose up -d postgres` → `cd api && uv run alembic upgrade head` → API 起動、`cd viewer && npm run dev`
2. 文書を表示し IDP実行。読取結果タブが「キー項目 / キー項目候補 / グリッド」の 3 区分で表示され、上部チップに「初回 · 日時」が出ること
3. キー項目とセルを編集すると「変更 N件」が増減し、元値に戻すと減ること。number / date 項目に正規化ヒントが出ること。空欄にすると「（値なし）」のプレースホルダ
4. 確定 → チップが「修正 · 日時 · ユーザ名」（primary）になり、修正した入力欄に鉛筆アイコン、履歴の先頭に「修正（ユーザ名）」の行、スナックバー「修正を保存しました」
5. 編集中に履歴の行選択 / IDP実行 / ヘッダの文書 ID 変更で確認ダイアログが出ること。キャンセルで変更が残り、破棄して続行で操作が実行されること
6. 編集中にリロードするとブラウザの離脱警告が出ること
7. 右ペインがパネル内でスクロールし、アクションバーが下部に固定されること

## 備考

- `hiddenFieldKeys` → `fieldDefs`（`document` ストア・`WorkPanel` prop）
- 履歴選択のガード時は先に読取結果タブへ戻してからダイアログを出す（未保存の編集内容が見える状態で判断できるように）
- 正規化ヒントはクライアント側の再現で、判定はサーバが正（`normalized_fields`）
- 排他制御なし（PoC 制限）。相互ハイライトは #118
