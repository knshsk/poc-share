# 概要

閲覧URL経由の閲覧・ダウンロードを文書ID・イベント種別・発生日時・端末情報とともに欠損・重複なく記録する。

## 変更内容

- `view_events` テーブル（追記型。`docs/data-model/view-events.md`）
  - document_id(FK) / view_token_id(FK・発行台帳との紐付け) / event_type(view・download) / occurred_at / client_ip / user_agent
  - **UNIQUE(document_id, occurred_at, event_type)** — 冪等キー（文書ID+イベント発生日時）をDB制約で構造的に担保。衝突時は挿入スキップ（配信は成功させ、記録の重複だけ防ぐ）
- 記録ポイント（APIプロキシ配信＝唯一の関門、の決定に基づき公開閲覧経路の配信成功時のみ）:
  - `GET /view/{token}/pages` 成功 → view（文書を開いた=1閲覧。ページ画像の個別取得は記録しない）
  - `GET /view/{token}/pdf` 成功 → download
  - 無効トークン・社内（認証済み）表示は記録しない（社内閲覧の履歴化要否は未確定のため仮置き）
- `GET /api/documents/{document_id}/events`（JWT必須）— 検証用一覧
- テスト7件: 欠損なし（配信成功=必ず1件）・重複なし（同一冪等キーの二重挿入防止）・画像取得での二重記録なし・無効トークン非記録・端末情報/トークン紐付け・一覧API
