# 概要

登録済文書に対しDocument Intelligence（prebuilt-layout+Query Fields）で項目抽出を実行し、生値・正規化値・項目別確信度を返却・履歴記録するIDP実行APIを追加します。

## 関連Issue

Closes #37

## 変更内容

- `idp_runs`テーブル追加（追記型実行ログ。migration付き）
- Document Intelligence境界アダプタ `api/app/di.py`（Protocol分離。APIキーまたはManaged ID認証、endpoint未設定時はプレースホルダ）
- クエリセット定義+パース・正規化・確信度分離 `api/app/idp_extraction.py`（純粋関数）
- `POST /api/documents/{document_id}/idp-runs` — 実行（JWT必須）。実行区分（初回/再実行）はサーバ側で既存実行有無から自動判定。DI失敗時は502+失敗レコード記録
- `GET /api/documents/{document_id}/idp-runs` — 実行履歴一覧
- 設定追加（`FACTONE_DI_ENDPOINT` / `FACTONE_DI_API_KEY` / `FACTONE_DI_TIMEOUT_SECONDS`）、`.env.example`追記
- アプリ設定の `.env` 参照をリポジトリルート固定に集約（`app/config.py`。cwd非依存化+compose用変数と同居のため `extra="ignore"`。ローカル設定ファイルを1本化）
- OpenAPI・TS型再生成、`docs/data-model/idp-runs.md`追加、`docs/develop-guide/api.md` 設定節更新
- 依存追加: `azure-ai-documentintelligence`

## 仮置き（確定後に見直し）

- クエリセットは検証用サンプルPDF様式に合わせた暫定（注文書: 得意先コード・品目コード・数量・納期・単価。見積: 文書番号・得意先コード・発行日・合計金額）
- 同期応答・タイムアウト120秒既定（処理時間目標の確定後に非同期化を再検討）
- WBS原価データは様式確定まで対象外
- 実行区分はリクエストで受けず、サーバ側自動判定（契約単純化・改ざん余地なし）
