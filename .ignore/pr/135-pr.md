# 概要

`corrected` 行を base にした連鎖修正で、`corrections` に最新差分だけが保存されるため 2 世代目以降で前世代の修正済みマークが消える問題を、`corrections` を根の機械実行に対する累積差分として保存することで解消する（Issue の方針 B の最小形。列追加・マイグレーション・Viewer 変更なし）。

## 関連Issue

Closes #128

## 変更内容

- `create_correction`: base が `corrected` 行なら base の `corrections` に今回のボディを重ねて保存（同一キー・同一セル座標は今回の値で上書き。セルは base の並びを維持し新規座標を末尾に追加）
- API テスト: 連鎖修正で累積・後勝ち・1 世代目の差分保持を検証
- ADR-0018: 決定を「累積差分」に追記、却下案に「Viewer が連鎖を辿る案」を追加
- `docs/data-model/idp-runs.md` / `docs/viewer/result-panel.md` / モデルコメント: 記述更新

## 動作確認方法

1. 文書を登録し IDP 実行 → 読取結果でキー項目 A とセルを修正して確定
2. 選択中の修正行（1 世代目）を base に、別のキー項目 B を修正して確定
3. 2 世代目の表示で、A・セル・B すべてに鉛筆マーク（修正済み）が付くこと
4. 履歴から 1 世代目を選ぶと A・セルのみにマークが付くこと

## 備考

- 連鎖修正で機械値に戻したキーも累積 `corrections` に残る（人が確認した値として「修正済み」扱い）。ADR-0018 影響欄に明記
- 既存データ: 本変更前に作成された 2 世代目以降の `corrected` 行は最新差分のみのまま。PoC データのため移行は行わない
