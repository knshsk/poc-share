# 概要

APIとViewerをAzureへデプロイ可能にする。コンテナ化・ACRクラウドビルド・Container Apps（API+Keycloak相乗り）のBicep・フロント同居配信の実装。

## 変更内容

コンテナ化:

- `api/Containerfile` — マルチステージ（node で viewer ビルド → uv ベースPython実行イメージへ成果物同梱。コンテキスト=リポジトリルート）。起動時に `alembic upgrade head` を実行（PoC単一レプリカ前提）
- ViewerのOIDC設定（`VITE_OIDC_AUTHORITY` 等）はビルド引数で焼き込み。`build-images.sh` がKeycloak FQDNをEnvironmentから解決して注入
- `keycloak/Containerfile` — 公式イメージ+realm JSON焼き込み（`--import-realm`・config-as-codeの同一定義投入。シークレット非含有）+`kc.sh build` 済み最適化イメージ（`--optimized` 起動で起動時リビルド回避）

API（同居配信の実装）:

- `app/static_serving.py` — `static_dir` 存在時のみSPA配信を有効化（catch-all）。API経路（`/api`・`/health`・`/view/{token}/pages|pdf`）が常に優先、`/view/{token}`・`/callback` はindex.htmlへフォールバック、パストラバーサル防止
- テスト5件（フォールバック・API優先・dist無し時の従来動作）

Bicep:

- `acr.bicep`（Basic・admin無効）/ `container-apps-env.bicep`（+Log Analytics）/ `identities.bicep` / `app-roles.bicep`（Blob Data Contributor・Cognitive Services User・Key Vault Secrets User・AcrPull）/ `api-app.bicep` / `keycloak-app.bicep`（共用PostgreSQL内別DB）
- **ユーザー割当マネージドID採用**: ACRプルにはアプリ作成前のロール付与が必要で、システム割当（アプリ作成時に生成）では順序が成立しないため
- `main.bicep`: `apiImage` / `keycloakImage` が空なら アプリ層スキップ（初回=コアのみ、イメージビルド後に有効化）
- `keycloak-app.bicep`: `KC_HOSTNAME` へContainer AppsのFQDNを注入（本番モードはhostname必須。未設定だと起動失敗＝実デプロイ検証で判明し修正）
- `revisionSuffix`（デプロイ時刻）をアプリテンプレートへ付与し、同一イメージタグ（latest）でも新リビジョン・再プルを強制（未付与だと再デプロイが反映されない＝実デプロイ検証で判明し修正）
- `postgresql.bicep` へ `factone` / `keycloak` DB追加

スクリプト・ドキュメント:

- `scripts/build-images.sh`（az acr build両イメージ）/ `scripts/deploy-apps.sh`（FQDN出力）
- `docs/develop-guide/deploy.md` — アプリ層の手順（コア→イメージ→アプリ）とデプロイ後の手動設定を追記
