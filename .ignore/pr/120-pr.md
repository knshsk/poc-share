# 概要

IDP 実行時に Document Intelligence の生応答（最終ポーリング GET の応答本文、ラッパ込み）を Blob にバイトのまま保存し、実行時の API バージョン・モデル ID・項目別の読取領域を `idp_runs` に記録する。生応答を取得する API を追加する。

## 関連Issue

Closes #113

## 変更内容

- DI アダプタ（`services/di.py`）: SDK の `cls` コールバックで最終ポーリング応答本文を bytes のまま取得。`QueryFieldResult` に `page_number` / `polygon`、`AnalysisResult` に `api_version` / `model_id` / `raw_response` を追加し、抽出を純粋関数 `build_analysis_result` に集約
- 抽出パース（`services/idp_extraction.py`）: `ParsedExtraction.regions`（項目別読取領域 `{key: {page_number, polygon} | null}`）を追加
- データモデル・マイグレーション（`c2f7a1d9e4b3`）: `idp_runs` に `field_regions` / `di_api_version` / `di_model_id` / `raw_response_ref`（すべて NULL 可）を追加
- 実行 API: 成功時に Blob `{tenant_id}/{document_id}/idp-runs/{run_id}.json` へ生応答を保存し、参照と DI 情報を記録。応答 `IdpRunResponse` に `field_regions` / `di_api_version` / `di_model_id` を追加（`raw_response_ref` は非公開）。失敗実行は保存せず 4 列 NULL
- 新設 `GET /api/v1/documents/{document_id}/idp-runs/{run_id}/raw-response`: Blob の bytes を `application/json` で無変換返却。404 `idp-run-not-found`（不在・他文書）/ `raw-response-not-found`（失敗実行）
- テスト: DI フェイクの拡張、`build_analysis_result` / `parse_analysis` の単体テスト、実行 API・raw-response API の統合テスト
- API 契約生成物（`docs/api/openapi.json`・`viewer/src/api/schema.d.ts`）の再生成
- ドキュメント: `docs/data-model/idp-runs.md`（列・構造・Blob 保存・API）、`docs/api/README.md`（エラーコード 2 件）、ADR-0019（DI 生応答を Blob にバイト保存）

## 動作確認方法

1. `podman compose up -d postgres` → `cd api && uv run alembic upgrade head` → `uv run pytest`（167 件通過）
2. DI 接続設定（`FACTONE_DI_ENDPOINT` 等）がある環境で、文書登録 → `POST /api/v1/documents/{id}/idp-runs` → 応答に `di_api_version` / `di_model_id` / `field_regions` が入ること → `GET /api/v1/documents/{id}/idp-runs/{run_id}/raw-response` で `status` / `analyzeResult` を含む JSON が返ること
3. ローカル Blob（`blob_backend=local`）では `api/.blob-data/default/{document_id}/idp-runs/{run_id}.json` が作成される
4. 失敗実行（DI 未設定で 502）では `raw-response` が 404 `raw-response-not-found` を返す
