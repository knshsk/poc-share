# 概要

Viewer（閲覧用URL経由を含む）から原本PDFをダウンロードした際、`{document_id}.pdf` 固定だった保存名をアップロード時のオリジナルファイル名にする。

## 関連Issue

Closes #95

## 変更内容

- `documents.original_filename`（varchar(255), NULL可）を追加（Alembic `f2a9c7d1e604`）。登録API で multipart `filename` の basename を保存（Windows/POSIX 区切り両対応、空は NULL、冪等再送では不更新）
- 原本DL 2経路（`GET /api/documents/{document_id}/pdf`, `GET /view/{token}/pdf`）を共通ヘルパ `pdf_response` に集約し、`Content-Disposition: attachment; filename="{document_id}.pdf"; filename*=UTF-8''<percent-encoded>` を返す（日本語ファイル名対応）
- `original_filename` が NULL の既存文書は従来どおり `{document_id}.pdf`
- Viewer: `filenameFromDisposition` ユーティリティを追加し、DocumentView / PublicView の保存名に使用
- `docs/data-model/documents.md` に列追加を反映

## 動作確認方法

1. `uv run alembic upgrade head`
2. `POST /api/documents` に日本語ファイル名（例 `見積書.pdf`）でPDFを登録
3. Viewer の原本DLボタン、および閲覧URL画面のDLボタンでダウンロードし、保存名が `見積書.pdf` になることを確認
4. マイグレーション前に登録済みの文書（`original_filename` NULL）は `{document_id}.pdf` で保存されることを確認

## 備考

- 既存文書のバックフィルはしない（アップロード時のファイル名は再取得不可）
- Power Automate 側が multipart の `filename` に実ファイル名を載せない場合は `{document_id}.pdf` にフォールバック
