# 概要

文書種別（Query Fields・閲覧URL発行可否）をコードのハードコードから `document_type_configs` テーブルのテナント別設定に移行し、CRUD APIを追加する。

## 関連Issue

Closes #81

## 変更内容

- `document_type_configs` テーブル新設（tenant_id + type_code 一意、フィールド定義は key/label/type のJSONB配列）。既存3種別（quote / order_project / order_route）をシード投入
- 設定CRUD API `/api/config/document-types` を追加（POST重複409・未登録404・使用中DELETE409・バリデーション422）
- `DocumentType` enum と `documents` のCHECK制約を廃止し、種別コードを自由値化（検証はアプリ層で設定テーブル参照。文書登録時に未登録種別は422）
- `parse_analysis` の正規化をキー名ハードコードからフィールド型（string/number/date）駆動に変更
- IDP実行の query_fields を設定テーブル由来に変更（設定未登録の残存文書は防御的に409）
- 閲覧URL発行可否を `shareable` 設定で判定（用途を顧客向けに限定しない列名。ADR-0002の判断はシードのデフォルト値として引き継ぐ）
- OpenAPI / Viewer型定義を再生成、`DocumentTypeValue` のenum参照を除去
- ADR-0014 起票
