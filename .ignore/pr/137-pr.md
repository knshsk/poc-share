# 概要

number / date 型の正規化判定が厳しく、`￥74,800` や `令和 8年 9月 4日` が「解釈できません」警告になっていた。正規化規則を実務書類向けに緩和し、Viewer のキー項目入力欄に初めから `74800` / `2026-09-04` が入る状態にする。DI の読取値（原典）は「読取値 …」として補足表示する。

## 関連Issue

Closes #136

## 変更内容

- サーバ `_normalize`（`api/app/services/idp_extraction.py`）
  - number: NFKC 正規化 → `¥ 円 , 、 空白` 除去 → 整数化
  - date: 西暦 `YYYY[-/.年]M[-/.月]D[日]`（ゼロ埋め任意）と和暦（令和/平成/昭和/R/H/S、元年可）を ISO 8601 に変換。暦上存在しない日付は null
- クライアント `viewer/src/utils/normalize.ts` を同規則に更新。入力値と同表記の「正規化値 …」ヒントは省略
- `ResultEditor` のキー項目入力欄の初期値を `normalized_fields`（null なら `raw_fields`）にし、差分判定もその値基準に変更。読取値が異なる項目は確信度バー下に「読取値 …」を表示し `aria-describedby` で紐付け
- 文書: `docs/data-model/idp-runs.md` に「正規化規則」節を追加、`docs/viewer/result-panel.md` 更新
- 既存の `normalized_fields` は再計算しない（追記型。再実行・修正確定で新規則適用）

## 動作確認方法

1. number 型項目に `￥74,800`、date 型項目に `令和 8年 9月 4日` を返す文書で IDP 実行
2. 読取結果タブで入力欄が `74800` / `2026-09-04`、その下に「読取値 ￥74,800」「読取値 令和 8年 9月 4日」が出ること
3. 正規化不能な値（例 `月末`）は従来どおり生値 + 警告が出ること
4. 入力欄を編集せず確定しても「変更 0件」のままであること
