# 概要

Viewer で修正した読取結果を、機械実行と同じ形で保存・取得できるようにする。人手修正は `idp_runs` に `run_type = 'corrected'` の行として追記し（ADR-0018）、`POST /api/v1/documents/{document_id}/idp-runs/{run_id}/corrections` で差分ボディを受けて base とマージした新しい行を返す。既存の一覧・詳細・`latest` からも修正行を取得できる。

## 関連Issue

Closes #115

## 変更内容

- `idp_runs` に `base_run_id`（自己参照 FK）/ `corrected_by` / `corrections`（jsonb）を追加し、`run_type` の CHECK に `corrected` を追加（Alembic `e1c9d4a7b283`。`corrected` 行のみ非 NULL を CHECK で強制）
- `IdpRunSummary` に `base_run_id` / `corrected_by`、`IdpRunResponse` に `corrections` を追加。OpenAPI / TS 型を再生成
- `apply_corrections`（`api/app/services/idp_extraction.py`）: 差分 `fields` / `table_cells` を base にマージ。変更キーのみ現在の文書種別設定の型で再正規化し確信度を null、テーブルは構造維持で `content` のみ差し替え。base に無いキー / セル座標は `UnknownCorrectionTarget`
- `POST …/idp-runs/{run_id}/corrections`: 201 `IdpRunResponse`。両方空・重複セル・2000 文字超は 422 `validation-error`、base 不在 / 他文書は 404 `idp-run-not-found`、base が失敗実行は 409 `idp-run-not-correctable`、未知キー / セルは 422 `unknown-correction-target`。`field_labels` / `pattern_matches` / `field_regions` / DI 情報 / 生応答参照は base からコピー、`corrected_by` は JWT の `preferred_username`（無い場合 `sub`）、`corrections` はリクエストボディを保存。`corrected` 行を base にした連鎖修正可
- `latest` が修正行を返し `?run_type=corrected` で絞り込み可（列挙拡張のみ）
- テスト: CHECK 制約（実 DB 直 INSERT）、`apply_corrections` 単体 9 件、API 正常系 / 異常系 / 認証 13 件、#113 持ち越しの Blob 保存失敗 → 500 で実行ログを残さない回帰テスト
- ドキュメント: `docs/data-model/idp-runs.md`（列・`corrected` 行の値・`corrections` 構造・API 一覧）、`docs/api/README.md`（エラーコード 2 件）、ADR-0018 新規、`docs/requirements/viewer.md` に VW-09 追加

## 動作確認方法

1. `podman compose up -d postgres` → `cd api && uv run alembic upgrade head` → `uv run pytest`
2. DI 接続設定がある環境で文書を登録し `POST /api/v1/documents/{id}/idp-runs` を実行
3. 返った `run_id` に対して `POST /api/v1/documents/{id}/idp-runs/{run_id}/corrections` にボディ `{"fields": {"TotalAmount": "1"}}` を送ると 201 で `run_type = "corrected"`、`base_run_id` が元の `run_id`、`confidence.TotalAmount` が null の行が返る
4. `GET /api/v1/documents/{id}/idp-runs/latest` がその修正行を返し、`?run_type=initial` で元の実行に戻る。`GET …/idp-runs/{corrected_run_id}/raw-response` は元の DI 生応答を返す

## 備考

- 排他制御は行わない（PoC 制限、spec §10）。同一 base への並行修正は両方追記され `latest` は新しい方を返す。本番前に `base_run_id` 一意制約等で再検討
- 再正規化の型は実行時点ではなく現在の文書種別設定を参照する（実行ログは型を保持していないため）
- `corrections` は省略キーの既定値（`fields: {}` / `table_cells: []`）を補って保存する
- Viewer の履歴での `corrected` 表示・修正 UI は #117 の範囲（`WorkPanel.vue` は未変更。`corrected` 行は現状「再実行」表示になる）
- #113 持ち越しの Blob 保存失敗回帰テストを本 PR に含めた
