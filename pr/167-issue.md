### 事象

DI の表セルの `content` が改行（`\n`）を含む場合（品名 + 規格のような複数行セル）、Viewer の読取結果タブはセルを 1 行の `<input>` で描画するため、改行が除去されて連結表示される。そのセルを編集して確定すると、修正値から改行が失われる。1 文字入力して元に戻しただけでも、`<input>` の値（改行なし）が元の `content`（改行あり）と一致しないため「変更 1件」の下書きが残る。

- `api/app/services/di.py` は DI の `content` を無加工で渡す
- `viewer/src/components/ResultTable.vue` のセルはネイティブ `<input>`（改行を保持できない）。#162 より前の `v-text-field` でも同じ挙動で、回帰ではない

PR #165 の作業中に行った最終レビューで見つかった（差分外の既存挙動）。実データでの発生頻度は未確認。

### 再現手順

1. 表のセルの `content` に `\n` を含む実行結果を用意する（例: `"コピー用紙\nA4 500枚"`。実データが無ければ詳細 API の応答を差し替える）
2. 読取結果タブでそのセルを表示する
3. セルに 1 文字入力し、すぐ削除して元の表示に戻す
4. アクションバーの「変更 n件」を確認する。続けて確定し、修正結果の `content` を確認する

### 期待する動作

- 複数行のセルの内容が、改行を保ったまま確認・編集できる（または、改行を含むセルは 1 行表示でも編集していない限り下書きにならず、確定で改行が失われない）

### 実際の動作

- 表示は改行が除去されて連結される（`コピー用紙A4 500枚`）
- 編集して元へ戻しても「変更 1件」が残る（幻の下書き）
- 確定すると、改行の無い値が修正として保存される

対応の方向（案）: 改行を含むセルだけ `<textarea>`（または複数行対応の入力）で描画する／下書きの同値判定を「改行を除去した元値」とも比較して幻の下書きを防ぐ、のいずれか。表の行高（32px 固定）との兼ね合いがあるため設計の判断が要る。
