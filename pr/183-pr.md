# 概要

`docs/`配下（`docs/business/`を除く）と各ディレクトリのREADME、計62件を書き直した。文章を読みやすくし、記述を現在の実装に合わせ、変更の経緯を述べる記述を削った。コードと`docs/api/openapi.json`は変えていない。

## 関連Issue

Closes #182

## 変更内容

### 文章と体裁

理由・経緯・条件を述べていた箇条書きを段落にした。環境変数・設定値・参照先などの並列データと、ADRの代替案は表にした。順序のある操作と、優先順位・排他条件を持つ記述は、番号付きリストか表で残している。1項目にカッコの入れ子で詰め込んでいた条件・例外・理由は、文に分けた。和欧文間の半角空白は除き、文体は常体のままである。

ステータスコードとエラーコードの書き方、「関連ドキュメント」節の表、トラブルシュートの表の列見出しは、文書間でそろえた。

箇条書きの比率は、`docs/architecture/api.md`（36.2%）を除いて25%以下にした。同文書に残る箇条書きは、すべて番号付きの処理手順である。

### 見出し

「詳細仕様への導線」を「関連ドキュメント」に改めた。見出し内の和欧文間の空白・ダッシュ・コロンを除いた（たとえば`` ### `routers/`（APIエンドポイント） ``、`# Azure構成`、ADR-0018〜0025の題）。目次の節の見出しは「文書一覧」にそろえた。

要件の`### VW-01: …`の形と、ルートの`README.md`の題は変えていない。アンカー付きリンク（`#読込中の表示`）は切れていない。

### 曖昧さの解消

読み手が意味を1つに決められない記述を、コードと設定の実体で確かめて、1通りに読める文に直した。たとえば`docs/azure/README.md`では、「定義の正」が`bicep/main.bicep`と`bicep/modules/`の両方を指すと分かるようにした。`docs/architecture/view-url.md`では、`Cache-Control: no-store`を付けるのがAPIの応答だと明記した。

### 実装との食い違いの訂正

文書の記述を、現在の実装に合わせて直した。主なものは次のとおり。

| 文書 | 直した内容 |
| --- | --- |
| `docs/architecture/api.md`、`overview.md` | 文書登録は、PDF判定の前に`document_id`を検査して422を返す |
| `docs/architecture/view-url.md` | レート制限は、制限中のIPからの要求を、有効なトークンでも429にする。公開閲覧の失敗時の表示は、失敗の種類ごとに書き分けた |
| `docs/data-model/idp-runs.md` | NFKC正規化は`string`型にも掛かる。抽出する項目は文書種別設定で決まる。領域はDI応答の`documents`の全要素から取る |
| `docs/data-model/view-events.md` | 冪等キーは内部ID・発生日時・種別 |
| `docs/viewer/display.md`、`result-panel.md` | エンドポイント表、矩形の条件、表の見出しを実装に合わせた。状態表示の記号は、文字ではなくアイコン |
| `docs/develop-guide/deploy.md` | 作成されるリソースの表をBicepに合わせた。`deploy-apps.sh`の引数と、Keycloakのrealmを再インポートする手順も直した |
| `docs/develop-guide/auth.md` | 動作確認の手順を、開始ダイアログを閉じてからログアウトする形にした |
| `api/README.md`、`viewer/README.md` | ディレクトリ構成に抜けていたファイルを足した |

ADRは決定時点の記録なので、実装に合わせて書き換えていない。要件文書も、意図を述べる文書なので書き換えていない。

### 経緯の削除

文書には現在の仕様だけを書くことにした。変更の記録、過去の状態を述べる記述、IssueとPRの番号への言及は削った。

`docs/api/README.md`の「外部利用者接続前の破壊的変更（記録）」は節ごと削り、記録をADR-0017の追記へ表として移した。ADR-0022の参照先もADR-0017に改めた。この節にあった現在の仕様は、いずれもほかの節か文書に書いてある。

## 備考

コミットは3段階に分けている。ディレクトリ単位の書き直し、文書間の表記の統一、実装との食い違いの訂正と経緯の削除（ディレクトリ単位）の順である。差分が大きいので、コミットごとに見ると追いやすい。

文書を実装に合わせる過程で、実装の側に確認が要る点が3つ見つかった。このPRでは、文書を実装どおりに書いている。

1. 閲覧URLのレート制限が、制限中のIPからの要求を、有効なトークンでも429にする。
2. `number`の正規化で、サーバがViewerより広い入力（`1_000`など）を受け付ける。
3. `scripts/`のコメントと`.env.example`に、古い設定ファイルのパスが残っている。
