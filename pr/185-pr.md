# 概要

認証後の画面にある開始ダイアログを「文書選択ダイアログ」に改め、利用者が開閉できるようにする。文書の表示中や取得に失敗した後でも、アプリバーからダイアログを開いて登録と参照ができる。ダイアログを閉じればアプリバーを操作でき、ユーザーメニューからログアウトもできる。

## 関連Issue

Closes #184

## 変更内容

- Viewerの状態機械（Mediator）
  - 状態`start`を、文書が無いことを表す`empty`に改名した
  - ダイアログの開閉は`documentPickerOpen`で持ち、`openDocumentPicker`と`closeDocumentPicker`で切り替える。受け付けるのは`empty`・`document`・`documentError`のときだけで、登録の送信中（`registering`）は閉じない
  - `register`を`document`と`documentError`でも受け付ける。表示中の文書は送信の時点で閉じる。未保存の修正があれば、送信の前に既存の破棄確認を挟む
  - 文書の読込を始めたら、ダイアログを閉じる。ログイン直後に`document_id`が無ければ、ダイアログを自動で開く
  - 書類種別の一覧が未取得なら、ダイアログを開いたときに取得する。取得に失敗しても、取得済みの一覧は上書きしない
- 文書選択ダイアログ（`StartDialog.vue`を`DocumentPicker.vue`に改名した）
  - タブ行の右端に閉じるボタン（×）を置き、Escでも閉じられるようにした。背景のクリックでは閉じない。登録の送信中は閉じるボタンを無効にする
  - 文書の表示中・取得失敗中に開くと、「文書IDで参照」タブで開く。入力欄には表示中の文書IDを入れて全選択する。文書が無いときは「文書を登録」タブで開く
  - 閉じた後は、開く前にフォーカスのあった要素へフォーカスを戻す。その要素が画面から消えていれば戻さない
  - ダイアログに、アクセシブルな名前「文書を開く」を付けた
- 文書が無いときは、本文に空状態を出す。空状態には「表示中の文書はありません」の文言と「文書を開く」ボタンを置く
- アプリバー
  - 文書タイトルを押すと、文書選択ダイアログを開く。文書IDの切替メニューは廃止した
  - 文書が無いときは、タイトルの位置に「文書を開く」ボタンを出す。左右の余白は文書タイトルとそろえた
- テストを追加・更新した
  - Mediatorは、開閉を受け付ける状態・表示中や取得失敗中からの登録・破棄確認・登録失敗・種別一覧の取得を確かめる
  - ダイアログは、初期タブ・×とEscと背景のクリック・フォーカスを確かめる。空状態とアプリバーのテストも足した
  - テストのファイル名を`start-dialog.test.ts`から`document-picker.test.ts`に改名した
- ドキュメントは`docs/viewer/display.md`・`docs/viewer/result-panel.md`・`docs/architecture/viewer.md`・`docs/develop-guide/auth.md`・`viewer/README.md`を更新した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。今回の変更を主に確かめるテストは、`tests/document-picker.test.ts`・`tests/mediator-document.test.ts`・`tests/app-header.test.ts`・`tests/document-view.test.ts`にある。

画面は、ローカルスタックを起動して確かめる。起動は`docs/develop-guide/local-stack.md`の「起動」、ログインは`docs/develop-guide/auth.md`の「3. 動作確認」に従う。手順3と手順7では、ローカルのDBに文書が登録される。

1. URLに`document_id`を付けずにログインする。ダイアログが「文書を登録」タブで開くことを確かめる。×で閉じると空状態が出て、ユーザーメニューからログアウトできる
2. アプリバーの「文書を開く」と、空状態の「文書を開く」で、それぞれダイアログを開く。×とEscで閉じ、背景のクリックでは閉じないことを確かめる。キーボードでボタンにフォーカスを当ててEnterで開き、Escで閉じると、そのボタンにフォーカスが戻る
3. 壊れたPDFで取得失敗画面に入り、そこから登録し直す（Issueに挙げた1つ目の不都合）。先頭だけがPDFのファイルを`printf '%%PDF-1.4\nbroken\n' > broken.pdf`で作り、「文書を登録」タブで任意の文書IDとともに登録する。登録は成功し、取得失敗画面になる。アプリバーの文書IDを押すと、「文書IDで参照」タブで文書IDが全選択された状態で開く。「文書を登録」タブに切り替え、別の文書IDで正しいPDF（`samples/quote-001.pdf`など）を登録すると、文書が表示される
4. 文書の表示中に文書タイトルを押すと、「文書IDで参照」タブで表示中の文書IDが全選択された状態で開く。そのまま別の文書IDを打ち、参照すると表示が切り替わる
5. 登録の送信中は×が無効で、Escでも閉じないことを確かめる。ブラウザの開発者ツールで通信速度を落とすと、送信中の状態を見やすい
6. 成功した実行結果がある文書を開き、読取結果の値を1つ書き換える。未保存のままダイアログを開いて登録すると、破棄の確認がダイアログの上に重なる。Escで閉じるのは破棄の確認だけで、ダイアログの入力は残る。IDP実行は実際のDocument Intelligenceを呼ぶので、実行結果が既にある文書を使う
7. 文書の表示中に、手順3で登録した文書IDと別のPDFで登録する。409のエラーがダイアログに出て、ダイアログは開いたままになり、背面は空状態になる
8. ウィンドウの幅を360px程度まで狭めても、タブ2つと×が1行に収まる
