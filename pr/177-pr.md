# 概要

本番ビルド（`npm run build` の成果物）で、Vuetify のユーティリティクラス（`pa-*` / `mb-*` / `bg-*` / `rounded-*` / `elevation-*` など）が部品の規則に負け、余白や色が dev と異なっていた不具合を直す。カスケードレイヤーの順を `index.html` の head の最初の `<style>` で宣言し、stylesheet の並びに左右されないようにする。#172（PR #173）で CSS の `<link>` を body の末尾へ移してから起きていた。

## 関連Issue

Closes #176

## 変更内容

- 原因: レイヤーの優先順は、各レイヤー名が文書内で最初に現れた順で決まる。ビルドでは `moveStylesheetsToBody` が CSS の `<link>` を body の末尾へ移す一方、Vuetify はテーマの CSS（`vuetify-utilities` レイヤー）を実行時に `<style id="vuetify-theme-stylesheet">` として head の末尾へ足す。head の `<style>` が `<link>` より前になり、`vuetify-utilities` が最下位になっていた。dev では Vite が CSS を head へ注入し、テーマの `<style>` はその後ろに入るため、正しい順だった
- `index.html`: head の最初の `<style>` の冒頭で、全レイヤーの順を宣言する。`app-reset`（`main.css`）を最下位に置き、以降は `vuetify/styles`（`vuetify/lib/styles/main.css`）冒頭の宣言と同じ順・入れ子にする。宣言した順は dev の実際の順と同じなので、dev の表示は変わらない
- テスト: `tests/css-layers.test.ts` を追加
  - head の最初の `<style>`（stylesheet の `<link>` より前）で、`app-reset` + `vuetify/styles` の宣言と同じ順にレイヤーを宣言している（Vuetify の更新でレイヤーの構成が変わると失敗する）
  - アプリの CSS（`src` の `.css` と `.vue` の `<style>`）と Vuetify の CSS（`vuetify/lib` 配下）が使うレイヤーを、すべて宣言している（宣言していないレイヤーは、最初に現れた stylesheet の位置で順が決まるため）
  - 上の 2 件が使う、`@layer` の名前の抽出（入れ子・コメント・レイヤー以外の括弧・`;` を省いた minify 後の CSS の扱い）
- `tests/typography-classes.test.ts`: import の順でレイヤーの順を保つ前提のテスト 2 件（`main.ts` で `main.css` を vuetify より先に読む、`vuetify-overrides.css` を `vuetify/styles` の後に読む）を削除する。宣言で順を固定したため、import の順はレイヤーの順に影響しない
- コメント: `main.css`・`vuetify-overrides.css`・`plugins/vuetify.ts`・`vite.config.ts` の、import の順でレイヤーの順が決まるという記述を、`index.html` の宣言に合わせて直す
- ドキュメント: `docs/architecture/viewer.md`（Viewer の構成）、`docs/viewer/display.md`「読込中の表示」、`viewer/README.md`（`index.html` の説明と、Vuetify の部品の上書きの説明）

変えていないもの: `moveStylesheetsToBody`（CSS の `<link>` を body の末尾へ移す処理）、各 CSS の import の位置、各レイヤーの中の規則。

## 動作確認方法

`cd viewer && npm run build && npm run preview` でログイン画面を開き、`npm run dev` の表示と見比べる（カードの内側の余白、「ログイン」ボタンの primary 色の塗り）。

ヘッドレス Chromium での計測（1440×900。ログイン画面と公開閲覧（`/view/{token}`、API の応答は差し替え）の全要素の computed style を dev と比較）:

- 修正前のビルド
  - レイヤーの順: vuetify-utilities → app-reset → vuetify-core → vuetify-components → vuetify-overrides → vuetify-final
  - dev と異なるプロパティ: ログイン画面 249 件、公開閲覧 311 件。例: カードの padding 32px → 0、角丸 8px → 4px、影（`elevation-2`）が弱くなる、ボタンの背景 primary → 白、アプリバーの文字色
- 修正後のビルド
  - レイヤーの順: dev と同じ（app-reset → vuetify-core → vuetify-components → vuetify-overrides → vuetify-utilities → vuetify-final）
  - minify なし（`--minify false`）のビルドは、両画面とも dev と全プロパティが一致する
  - 通常のビルドで残る差は、minify による表記・丸めだけ（数値の差は最大 0.031px、`transition-*` の一覧の展開、`-webkit-mask-size` の付加、`background-position` の `0% 0%` と `0px 0px`）。見た目には表れず、この修正とは関係しない

## 備考

- #173 以降のビルドを配信している環境では、同じ崩れが出ている
- Vuetify を更新してレイヤーの構成（名前・入れ子・順）が変わると、`tests/css-layers.test.ts` が失敗する。そのときは `index.html` の宣言を `vuetify/styles` の冒頭の宣言に合わせる
- アプリの CSS に新しいレイヤーを足すときは、`index.html` の宣言にも位置を決めて足す（宣言漏れはテストが検出する）
