# 概要

画面から文書を登録して失敗したとき、APIの英語のエラー文言ではなく、日本語で失敗の理由を表示する。文書IDの形式の誤りのように利用者が直せる失敗では、何を直せばよいかが分かる文言にする。

## 関連Issue

Closes #198

## 変更内容

これまでは、登録に失敗すると、409のときだけ「文書IDは別の内容で登録済みです」を表示していた。それ以外の失敗では、APIが返すProblem Detailsの`detail`（英語の説明文）をそのまま表示していた。

- 文言の決め方: Mediatorは、Problem Detailsの`type`で失敗の種類を見分け、文言を決める。`detail`は画面に出さない。内部イベント`registerFailed`には、文言の代わりにAPIのエラー応答（`problem`）を入れる。通信に失敗したときは`problem`を入れない
- 失敗ごとの文言は次の表のとおり。409の文言と、どれにも当たらない失敗の文言（登録に失敗しました）は従来のまま

  | 失敗の原因 | 応答 | 文言 |
  | --- | --- | --- |
  | 文書IDが、別の内容ですでに登録されている | 409 `document-conflict` | 文書IDは別の内容で登録済みです |
  | 文書IDが255文字を超える | 422 `validation-error`（`errors`あり） | 文書IDは255文字以内で入力してください |
  | 文書IDが`/` `\`・制御文字・双方向制御文字を含むか、`.` `..`そのものである | 422 `validation-error`（`errors`なし） | 文書IDに使用できない文字が含まれています |
  | 拡張子はPDFだが、ファイルの中身がPDFではない | 415 `unsupported-media-type` | PDFではないファイルが選択されています |
  | PDFとして開けない。壊れたPDFや、閲覧パスワード付きのPDFが当たる | 422 `invalid-pdf` | PDFを開けません。壊れているか、閲覧パスワードが設定されています |
  | 書類種別の一覧を取得した後に、選んだ種別の設定が削除された | 422 `unknown-document-type` | 選んだ書類種別は削除されています。書類種別を選び直してください |
  | 上記以外の失敗 | 401・403・500など。通信に失敗して応答が無い場合も含む | 登録に失敗しました |

- 文書IDの誤りの見分け方: 画面からの登録では、書類種別は一覧から選び、PDFも必須のため、`validation-error`になるのは文書IDの誤りだけである。`errors`が付くのは、文書IDが255文字を超えたときである。付かないのは、APIが文書IDの文字を検査して拒否したときである。`/`を含むのか制御文字を含むのかは、`detail`の文字列でしか分からない。ADR-0016は、エラーの種類を`detail`の文字列ではなく`type`で判別すると定めている。そのため、この2つは見分けずに1つの文言にした
- 書類種別の一覧の取り直し: `unknown-document-type`のときは、一覧を取り直す。一覧はセッションの間使い回すので、取り直さないと、削除された種別が選択肢に残り続ける。選択欄に入っている値は消さない。消すと登録ボタンが無効になり、押したボタンからフォーカスが外れるためである。一覧に無い値になるので、選択欄には種別コードがそのまま表示される
- テスト: `tests/mediator-document.test.ts`で、`type`ごとの文言と、それ以外の応答・通信の失敗での既定の文言を確かめる。`unknown-document-type`のときだけ一覧を取り直すことも確かめる。既存のテストにある409の応答は、APIが返す本文と同じ形にした
- ドキュメント: `docs/viewer/display.md`（文書選択ダイアログ）に、失敗ごとの文言と一覧の取り直しを追記した。`docs/architecture/viewer.md`（文書表示の節）には、`type`から文言を決めることを追記した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

画面では、文書選択ダイアログの「文書を登録」タブで書類種別を選び、次の文書IDとファイルで登録する。どの手順でも、文書は登録されない。手順1〜5はAPIが保存の前に拒否し、手順6は要求がAPIに届かない。

1. 文書IDに`a/b`を入力し、PDFを選ぶ。「文書IDに使用できない文字が含まれています」が出る
2. 文書IDに256文字の文字列を入力し、PDFを選ぶ。「文書IDは255文字以内で入力してください」が出る。文字列は`python3 -c "print('a' * 256)"`で作れる
3. 文書IDに`test-198`を入力し、拡張子を`.pdf`にしたテキストファイルを選ぶ。「PDFではないファイルが選択されています」が出る。ファイルは`printf 'not a pdf' > fake.pdf`で作れる
4. 文書IDに`test-198`を入力し、`api/tests/fixtures/broken.pdf`を選ぶ。「PDFを開けません。壊れているか、閲覧パスワードが設定されています」が出る
5. 登録済みの文書IDと書類種別を指定し、その文書とは別のPDFを選ぶ。「文書IDは別の内容で登録済みです」が出る
6. 開発者ツールのNetworkタブで通信をOfflineにして登録する。「登録に失敗しました」が出る

`unknown-document-type`は、一時的な書類種別を作ってから削除して確かめる。認証済みのアクセストークンを`$TOKEN`に入れておく。

1. 書類種別「一時種別」（`tmp_198`）を作る

    ```bash
    curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"type_code":"tmp_198","display_name":"一時種別","shareable":false,"fields":[{"key":"no","label":"番号","type":"string"}]}' http://localhost:8000/api/v1/config/document-types
    ```

2. Viewerを再読み込みしてから、文書選択ダイアログの「文書を登録」タブを開く。書類種別の選択肢に「一時種別」が並ぶ
3. ダイアログを開いたまま、「一時種別」を削除する

    ```bash
    curl -s -X DELETE -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/config/document-types/tmp_198
    ```

4. 「一時種別」を選び、文書ID`test-198`とPDFを指定して登録する。「選んだ書類種別は削除されています。書類種別を選び直してください」が出る。文書は登録されない
5. 書類種別の選択欄には`tmp_198`が表示される。選択欄を開くと、「一時種別」は選択肢から消えている
