# 概要

キャンバスのツールバーから「高さに合わせる」を削除し、フィットを「幅に合わせる」「ページ全体を表示」の 2 つにする。右ペインの幅を広げてキャンバスを狭めたとき、「高さに合わせる」だけがページの高さを保って横スクロールバーを出し、ほかのフィットと操作感がそろわなかったため。

## 関連Issue

Closes #170

## 変更内容

- `DocumentCanvas`: 「高さに合わせる」のボタン（`canvas-fit-height`）と `PhArrowsVertical` の import を削除。フィットは「幅に合わせる」「ページ全体を表示」の 2 つで、表示領域の変化に追従し、± の操作で手動になる（従来どおり）。初期表示は「ページ全体」のまま。公開閲覧も同じコンポーネントのため同じ
- `utils/zoom.ts`: `ZoomMode` から `height` を除き、`fitZoom` を幅合わせ・ページ全体の 2 種にする
- CSS の `ponytail:` 注記（横スクロールバーの高さを考慮しない）の前提を「手動の倍率で横にはみ出した状態から全体表示にしたとき」に改めた（高さ合わせが無くなり、横にはみ出すのは手動の倍率のときだけになったため）
- テスト: 高さ合わせのケースを削除し、倍率の下限 1・25〜200% に制限しないこと・± のスナップはページ全体で確認するよう付け替えた。ボタンが無いことを確かめるテストは足していない（削除したものが無いことを確かめるだけのテストになるため）
- ドキュメント: `docs/viewer/display.md`（モード・フィットの定義・ツールバー）、`viewer/README.md`

## 動作確認方法

ローカル環境で testuser ログイン後、文書を開き、キャンバスのツールバーのフィットが 2 つであることと、境界を操作したときの追従を確認する。

ヘッドレス Chromium での確認（1440×900、`order-sample-001`、右ペイン 528 / 736 / 400px）:

- フィットのボタンは `canvas-fit-width` と `canvas-fit-page` の 2 つ
- ページ全体: 61 / 61 / 61%、ページ枠 484px で不変
- 幅合わせ: 106 / 79 / 122%、ページ枠 841 / 627 / 968px
- 手動（ページ全体から拡大 1 回）: 75 / 75 / 75%、ページ枠 595px で不変
- いずれも倍率ラベル = ページ枠の幅 ÷ ページ実寸幅（#168）

## 備考

- 主要な PDF ビューアでも、フィットは表示領域の変化に追従する（pdf.js と Chrome はリサイズ時にフィットを再適用し、Acrobat の「幅に合わせる」も表示領域に対する相対指定）。pdf.js と Chrome のボタンは「ページ全体」「幅」だけで、高さ合わせは持たない。出典は #170 の関連情報
