# 概要

公開閲覧の`User-Agent`と接続元IP、DIの例外メッセージを、APIは列の長さを確かめずにDBへ保存していた。値が列の長さを超えると500になり、閲覧イベントや失敗したIDP実行も記録されなかった。扱いは、値を保存する目的と出所で分けた。`User-Agent`は512文字で切り詰め、接続元IPはIPアドレスとして解釈できない値を`unknown`にする。DIの例外メッセージは、列を`text`に変えて全文を保存する。

## 関連Issue

Closes #197

## 変更内容

- `api/app/routers/view_urls.py`
  - `_record_event`: `User-Agent`を、列の長さの512文字で切り詰めて保存する。分析に使うブラウザ・OSの情報は先頭にある。閲覧者が任意の長さで送れる値なので、列は広げない
  - `_client_ip`: IPアドレスとして解釈できない値と、ゾーンID付きのIPv6アドレスを`unknown`にする。閲覧イベントと失敗記録の`client_ip`、レート制限のキーは、どれもこの値を使う。uvicornは既定で、接続元が127.0.0.1の要求に限り`X-Forwarded-For`の値を接続元にするため、任意の文字列が入りうる。切り詰めた文字列はIPアドレスとして使えないので、切り詰めない。ゾーンIDを受け付けないのは、Pythonの`ipaddress`がその長さを制限しないためである
- `api/app/models.py`・`api/migrations/versions/c4d931791740_change_idp_runs_error_info_to_text.py`: `idp_runs.error_info`を`varchar(2048)`から`text`に変え、DIの例外メッセージを全文保存する。Azure SDKの例外メッセージは、原因の特定に要る詳細（`Inner error`など）を末尾に置くためである。PostgreSQLは、この型の変更で表を書き換えない。downgradeは、2048文字を超える値があると失敗する。旧スキーマでは表現できない値を、切り詰めて黙って失わないためである
- テスト
  - `tests/test_view_events.py`: 600文字の`User-Agent`でも閲覧が200になり、先頭512文字を記録すること。接続元がIPv4・IPv6のアドレスならそのまま記録すること。IPアドレスでない100文字の値やゾーンID付きのIPv6アドレスなら、閲覧が200になり、`unknown`を記録すること
  - `tests/test_view_url.py`: 既存の失敗記録のテストに、接続元が`unknown`になることの確認を足した。テストクライアントの接続元（`testclient`）はIPアドレスではない
  - `tests/test_idp_runs_api.py`: 3000文字のDIの例外メッセージでも502になり、失敗した実行に全文を残すこと
- ドキュメント: ADR-0028を追加した。`docs/architecture/view-url.md`の「`X-Forwarded-For`は見ない」という記述は、uvicornの挙動に合わせて直した。あわせて、`docs/architecture/api.md`と`docs/data-model/`の`view-events.md`・`view-tokens.md`・`idp-runs.md`を更新した

## 動作確認方法

自動テストは、`api/`で`uv run pytest`を実行する。マイグレーションを含むため、手元のDBで確かめる前に`api/`で`uv run alembic upgrade head`を実行する。

公開閲覧は、Viewerで見積書の文書の閲覧URLを発行して確かめる。次のコマンドの`{token}`は、閲覧URLの`/view/`に続く部分に置き換える。

1. 600文字の`User-Agent`を付けて送る。200が返る

    ```bash
    curl -s -o /dev/null -w '%{http_code}\n' -H "User-Agent: $(python3 -c "print('a' * 600)")" http://localhost:8000/view/{token}/pages
    ```

2. APIを動かしているホストから`127.0.0.1`宛てに、100文字の`X-Forwarded-For`を付けて送る。200が返る。存在しないトークンで送ると404が返る

    ```bash
    curl -s -o /dev/null -w '%{http_code}\n' -H "X-Forwarded-For: $(python3 -c "print('a' * 100)")" http://127.0.0.1:8000/view/{token}/pages
    ```

3. 認証済みのアクセストークンを`$TOKEN`に入れ、文書の閲覧イベントを取得する。手順1のイベントは`user_agent`が512文字になり、手順2のイベントは`client_ip`が`unknown`になる

    ```bash
    curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/documents/{document_id}/events
    ```

DIの例外メッセージの全文保存は、実際のDIで長い例外を起こせないため、自動テスト（`tests/test_idp_runs_api.py`）で確かめる。

## 備考

本番（Container Apps）では、APIに接続するのはingressである。uvicornは127.0.0.1以外からの`X-Forwarded-For`を信頼しないので、`client_ip`はingressのIPになる見込みである。その場合、IP単位のレート制限も全利用者で1つの枠を共有する。原因と直し方がこのPRとは異なるため、#205 で扱う。
