# 概要

Viewerの読取結果タブに、array型の項目（明細）を表示する。明細の値を修正・確定できるようにし、明細の値とキャンバスの根拠の矩形を相互にハイライトする。明細は原本の表と同じ並びの表で示し、選択中の値の状態・読取値・正規化ヒントは表の下の詳細欄に出す。キー項目・表（レイアウト認識のテーブル）の挙動は変えない。

このPRは統合ブランチ`feature/213-engine-neutral-extraction`に向ける。これで #214 〜 #216 がそろうので、統合ブランチを検証環境で確かめてから`main`へ取り込む（#213）。

## 変更内容

- 読取結果タブに、array型の項目ごとの区分を追加した（`ResultEditor`）
  - 区分はキー項目と候補値の間に置き、見出しは項目のラベルと行数とする。複数あれば文書種別設定の順に並べる
  - 設定で`visible=false`の項目は出さない。行が0件なら「行がありません」と出す
- 明細の表と詳細欄の部品`ItemTable`を追加した
  - 見た目は表（`ResultTable`）にそろえ、先頭に行番号の列を置く。行番号の列は横スクロールしても左に残る
  - 列はプロパティごとに置き、設定の`properties`の順に並べる。設定に無いプロパティ（設定変更後の実行）は末尾に置く
  - 列幅は見出しと元の値から決め、入力中には変えない。number型は右寄せにする
  - セルには、下書きの塗り、修正済の三角印、未読取の「（値なし）」、低確信度（80%未満）の警告アイコンを付ける。低確信度の値に入力しても警告アイコンは残し、入力中に文字の位置を動かさない
  - 詳細欄には、選択中の値の位置（「n行目・ラベル」）・状態・読取値・正規化ヒントを出す。状態・読取値・正規化の規則はキー項目と同じとする
- 明細の値の修正を、キー項目と同じ下書きに記録するようにした（`Draft.items`、イベント`itemInput`）
  - 空欄はnull（値なし）とし、元の値に戻すと差分から外す
  - 変更件数に含めるので、破棄・未保存の確認ダイアログ・離脱時の警告は明細にも効く
  - 確定では、修正のボディの`items`（`field` / `index` / `property` / `value`）に入れて送る
- キャンバスに、明細の値の読取矩形を追加した
  - IDは`item:{field}:{index}:{property}`、ツールチップは「{項目ラベル} {n}行目 {プロパティラベル}」とする
  - 矩形を選ぶと区分を開いて入力欄へフォーカスし、入力欄にフォーカスすると矩形を選択する
- 明細の表は`role="group"`で項目ラベルを名前に持つ。セルの読み上げ名は「n行目 ラベル」で、状態と読取値は`aria-describedby`で読み上げる
- キー項目と明細の状態の表示（文言・アイコン・色）を、共通の部品`FieldStatusBadge`にまとめた。キー項目の見た目は変えていない
- `ResultEditor` / `KeyFieldList`のコメントに残っていたDI固有の名前を改めた
- テストの追加・更新
  - 純関数: 明細の並び（設定順・設定に無い項目とプロパティ・非表示）、ID、元の値、矩形の条件と描画順
  - Mediator: `itemInput`による差分の増減、確定のPOSTの`items`、明細だけの未保存の変更での確認ダイアログ
  - コンポーネント: 列見出し・行番号・セルの手掛かり・詳細欄・正規化ヒント・読み上げ、下書きの更新で入力欄が作り直されないこと、明細の区分の並び・0件・畳んだ区分へのフォーカス
- ドキュメント: `docs/viewer/`（result-panel・display）、`docs/architecture/viewer.md`、`docs/data-model/document-type-configs.md`を更新した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

画面の確認には、`engine`が`azure-cu`で明細の項目を持つ文書種別と、その文書の成功した実行結果が要る。実行結果が無ければ、IDP実行を1回行う（CUの呼出の分だけ課金される）。

1. Viewerでその文書を開き、読取結果タブのキー項目と候補値の間に、明細の区分（項目のラベルと行数）が出ることを確かめる
2. 明細の表で、列見出しが設定のプロパティの順に並び、低確信度の値に警告アイコン、値の無いセルに「（値なし）」が付くことを確かめる
3. キャンバスで明細の値の矩形を押す。読取結果タブの該当のセルにフォーカスが移り、詳細欄に「n行目・ラベル」と状態が出ることを確かめる
4. そのセルに数文字を入力する。入力中にフォーカスが外れず、アクションバーの「変更 N件」が増え、詳細欄の状態が「未保存」になることを確かめる。number型のセルに数値以外を入れると、詳細欄に「数値として解釈できません」が出る
5. [確定]を押す。新しい修正行が選択され、直したセルの右上に修正済みの三角印が付くことを確かめる
6. 明細の区分の見出しを押して畳んでから、キャンバスで明細の矩形を押す。区分が開き、該当のセルにフォーカスが移ることを確かめる
7. 右ペインを狭めて表を横スクロールしても、行番号の列が左に残ることを確かめる

`engine`が`azure-di`の文書種別の文書では、明細の区分が出ず、キー項目・候補値・表の表示と修正が今までどおり動くことを確かめる。

## 備考

- 読取値（正規化前の値）の表示規則は、キー項目と同じにした。正規化で表記だけが変わる値（金額のカンマ、全角の括弧など）にも「読取値 …」が出る。表示規則の見直しは別途検討する
- 明細の行の追加・削除はできない
