# 概要

アプリバーの文書 ID バッジを、原本ファイル名を主表示にした文書タイトルに置き換える。原本ファイル名は DB（`documents.original_filename`）に保存済みだったため、文書メタデータの応答に項目を追加して Viewer まで渡す。UI 是正 第2弾（親 #159）の 1 件目。

## 関連Issue

Closes #160

## 変更内容

- API: `DocumentResponse`（`POST /api/v1/documents` の 201 / 200 と `GET /api/v1/documents/{document_id}` で共用）に `original_filename: str | None` を追加。DB 列は既存のためマイグレーションなし。項目の追加のみで後方互換。`docs/api/openapi.json` と `viewer/src/api/schema.d.ts` を再生成
- Viewer（Mediator）: `LoadedDocument.originalFilename` → `HeaderVm.documentName` として渡す。イベントの追加なし
- `AppHeader`: ロゴ | 縦の区切り線 | 文書タイトル [種別チップ + 原本ファイル名（16px / 500）+ 文書 ID（小・等幅）+ ⌄]
  - ファイル名の無い文書（ファイル名なしの登録・列追加前の行）と読込中は文書 ID を主表示にする（ID は二重に出さない）
  - 長いファイル名は省略記号で切り、全文を `title` 属性に入れる
  - クリックで開く文書 ID の再入力メニュー、公開閲覧（`/view/{token}`）のロゴのみ表示、既存の `data-testid` は現行どおり
- ドキュメント: `docs/viewer/display.md`（ヘッダー）、`docs/architecture/viewer.md`（構成図・文書表示フロー）、`docs/data-model/documents.md`（`original_filename` の用途）

無認証の `/view/{token}` 系の応答には変更なし（`DocumentResponse` を返さない。ファイル名が出るのは従来どおり原本ダウンロードの `Content-Disposition` のみ）。

## 動作確認方法

ローカル環境で testuser ログイン後、`/?document_id=<ファイル名付きで登録した文書ID>` を開く。ヘッドレス Chromium での確認結果（1440×900 / 1280×720）:

- ヘッダーに「種別チップ + `quote-001.pdf`（16px / 500）+ 文書 ID」が表示され、ロゴの左端は x=16
- タイトルのクリックで文書 ID の再入力メニューが開き、現在の文書 ID が入っている
- 応答の `original_filename` を null に差し替えると、文書 ID だけが 1 回表示される
- 124 文字のファイル名は省略記号で切れ、`title` に全文が入り、アプリバーからはみ出さない
- 公開閲覧（発行した閲覧URL を未認証で開く）はロゴのみ
