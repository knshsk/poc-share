# 概要

見積書のシードの2種別（`quotation`・`quotation_di`）で、発行元と宛先のラベルが逆に表示される問題を直す。共通8項目のラベルと表示有無は、注文書の向き（発行元が取引先、宛先が自社）に合わせてある。見積書は自社が発行し、宛先が取引先になるため、そのままでは発行元（自社）が「取引先」として表示され、宛先（取引先）が「自社名」として表示されなかった。

このPRは統合ブランチ`feature/213-engine-neutral-extraction`に向ける。

## 関連Issue

Closes #221

## 変更内容

- マイグレーション`f1a6c3e8b2d4`を追加した。`tenant_id`が`default`の`quotation`・`quotation_di`だけで、次のとおりラベルと表示有無を入れ替える。キーと説明は変えない。注文書の種別は変えない
  - `SenderCompanyName`（発行元）: ラベルを「自社名」にし、表示しない（`visible: false`）
  - `ReceiverCompanyName`（宛先）: ラベルを「取引先」にし、表示する（シードのほかの項目と同じく`visible`を持たない）
  - downgradeで元に戻す
- テスト: マイグレーションのテストに、見積書の2種別だけが入れ替わること、ほかの種別が変わらないこと、downgradeで戻ることの確認を追加した
- ドキュメント: `docs/data-model/document-type-configs.md`に見積書のラベルと表示有無の扱いを書き、ADR-0029の追記に理由を足した。`conftest.py`のテスト用の種別のコメントを直した

## 動作確認方法

1. `cd api && uv run pytest tests/test_migrations.py`を実行し、すべて通ることを確かめる
2. ローカルのDBで`uv run alembic upgrade head`を実行する。`GET /api/v1/config/document-types`で、`quotation`・`quotation_di`の`SenderCompanyName`がラベル「自社名」・`visible: false`、`ReceiverCompanyName`がラベル「取引先」で`visible`を持たないことを確かめる。`purchase_order`・`purchase_order_di`は変わらない
3. `uv run alembic downgrade c4f8a2e6d9b1`で元のラベルと表示有無に戻ることを確かめる

## 備考

- 外部システムはキーで値を読むため、ラベルの変更による影響はない
- 実行ログの`fields[key].label`は、実行時点のラベルのスナップショットである。一方、Viewerの表示有無は現在の設定で決まる。そのため、このマイグレーションより前の見積書の実行結果では、宛先の会社名が元のラベル「自社名」のまま表示され、発行元は表示されなくなる
