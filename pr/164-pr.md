# 概要

右ペインの幅をキャンバスとの境界で変えられるようにし、上部の選択中結果チップを「表示中 … 最新 / 過去の結果」に置き換える。あわせて UI 是正 第1弾（#157）の持ち越し（一覧の取得失敗と IDP 実行失敗の区別、閲覧URL 一覧の階層）を解消する。UI 是正 第2弾（親 #159）の 2 件目。

## 関連Issue

Closes #161

## 変更内容

- `DocumentView`: キャンバスと右ペインの境界（幅 6px、`role="separator"`、`aria-controls` / `aria-valuenow` / `aria-valuemin` / `aria-valuemax`）を追加
  - ドラッグ（`setPointerCapture` と要素自身の `pointermove`。window へのリスナーは足さない）、←（+16px）/ →（−16px）キー、ダブルクリックで既定 528px
  - 最小 400px、最大はキャンバスが 320px 残る幅。幅は保存しない（リロードで既定に戻る）。幅 960px 未満の縦積みでは境界を出さない
  - 幅は CSS 変数 `--pane-width` で渡し、列定義は stylesheet 側の `min(var(--pane-width), calc(100% - 326px))`。ウィンドウを縮めたときは CSS が即座に上限を効かせ、レイアウトの `ResizeObserver` が状態（`aria-valuenow`）も上限へ丸める
  - キャンバスのフィットは `DocumentCanvas` の既存の `ResizeObserver` が追従する
- `WorkPanel`: 選択中結果のチップを「表示中 {区分}（{修正者}）{日時}」+「最新」/ 警告色の「過去の結果」に置き換え。クリックで実行履歴タブへ（既存の `tabChanged`）。実行履歴の先頭行にも「最新」
  - 幅が足りないときは IDP実行 の下へ折り返し、それでも収まらないときは区分・日時を省略記号で切る（チップは必ず残す。全文は `title`）
  - `data-testid`: `selected-run-chip` → `showing-run`（チップは `showing-run-age`）
- Mediator: `Model.runsLoadFailed`（`runsFailed` で true、再取得・成功・文書切替で false）→ `WorkPanelVm.runsLoadFailed`。`noRuns` の `!vm.error` を置き換え、実行 0 件の文書で IDP 実行が失敗した直後も塗りの IDP実行 と案内が残るようにした。イベントの追加なし
- 文言: 認証後のダウンロードボタン「原本DL」→「原本ダウンロード」（公開閲覧の「ダウンロード」は不変）
- `ViewUrlPanel`: 期限の行を 12px にして発行日時（14px）と階層を付ける
- ドキュメント: `docs/viewer/display.md`、`docs/viewer/result-panel.md`、`docs/architecture/viewer.md`

変えていないもの: Mediator のイベント、`EditorVm` / `CanvasVm` の型、上記以外の `data-testid`、IDP実行ボタンの位置、初期ズーム、フッター、公開閲覧の挙動。

## 動作確認方法

ローカル環境で testuser ログイン後、文書を開いて境界を操作する。ヘッドレス Chromium での確認結果（1440×900）:

- 既定 528px。境界のドラッグで約 737px、離した後は追従しない。←→ で ±16px、ダブルクリックで 528px
- 最小 400px、最大 1114px（キャンバス 320px 残し、`aria-valuemax` = 1114）。ウィンドウを 1100px 幅に縮めると右ペイン・`aria-valuenow`・`aria-valuemax` がいずれも 774 になり、→キーが 1 回目から効く。900px 幅では境界が非表示
- 幅合わせのフィットが幅の変更に追従する。ドラッグ中にテキストは選択されない
- 「表示中」= 最新、実行履歴の先頭行に「最新」、2 行目を選ぶと警告色の「過去の結果」。クリックで実行履歴タブへ
- 右ペイン 400px では「表示中」が IDP実行 の下へ折り返し、区分・日時は省略記号、チップはペイン内に残る（36 文字の修正者名でも同じ）。既定 528px・通常のラベルでは折り返さない
- 実行 0 件（一覧の応答を空に差し替え）で塗りの IDP実行 + 案内。IDP 実行の 500（差し替え。実 API は呼ばない）でも塗りと案内が残る。一覧取得の 500 では outlined・案内なし
- ダウンロードボタンが「原本ダウンロード」、閲覧URL 一覧の期限が 12px

## 備考

- 実装後に全体レビューと over-engineering レビュー（ponytail-review）を実施。ponytail-review は指摘なし。全体レビューの指摘（狭い幅で「過去の結果」チップが切れる、`aria-controls`、テストの stub 復元、コメント）は最後のコミットで反映済み
- 見送り（必要になったら対応）: 境界の当たり判定が 6px（判定だけ広げるとキャンバス右端のスクロールバー操作を奪うため）、マルチポインタ時の `lostpointercapture` の照合、ウィンドウを縮めて戻しても幅は戻らない（一般的な splitter の挙動）
- 第2弾の残り: #162（読取結果エディタの再設計）
