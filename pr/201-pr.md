# 概要

書類種別一覧の取得に失敗したとき、文書選択ダイアログの「文書を登録」タブにエラーと「再試行」ボタンを出す。ダイアログを開いたまま、一覧を取得し直せる。

## 関連Issue

Closes #190

## 変更内容

これまでは、書類種別一覧（`GET /api/v1/config/document-types`）の取得に失敗しても、画面には何も出なかった。書類種別の選択肢が空になり、登録ボタンを押せない理由が利用者には分からなかった。ダイアログを開き直すと一覧を取得し直すが、そのことも画面からは分からなかった。

- 失敗の表示: 取得に失敗すると、`DocumentRegisterForm`はタブの先頭にエラー「書類種別の一覧を取得できませんでした」を表示し、その右端に「再試行」ボタンを置く。見た目は登録エラーと同じ`v-alert`（`type="error"`・`variant="tonal"`）で、`role="alert"`によりスクリーンリーダーが読み上げる
- 再試行: 「再試行」ボタンは、新しいイベント`retryDocumentTypes`をbubbleする。応答を待つ間はエラーを残し、ボタンを`loading`で読込中の表示にする。`disabled`にすると押した直後にキーボードのフォーカスが外れるので、付けていない。取得できるとエラーとボタンが消えるので、ボタンにあったフォーカスを書類種別の選択欄へ移す。応答を待つ間に利用者が別の入力欄へ移っていれば、フォーカスは動かさない
- Mediator: 一覧の取得を`loadDocumentTypes`にまとめ、ダイアログを開いたときと再試行のときに呼ぶ。応答を待つ間は`register.typesLoading`を立て、開き直しや再試行が重なっても要求を1本にする。取得に失敗すると、新しい内部イベント`documentTypesFailed`で`register.typesFailed`を立て、取得できたら戻す。応答は、ダイアログを閉じた後や文書の読込中に届いても受け取る。捨てると`typesLoading`が立ったまま残り、一覧を取得し直せなくなるためである
- ViewModel: `RegisterVm`は、モデルの`register`に`submitting`を足した型にした（`ViewUrlsVm`と同じ作り）。種別一覧の取得状態（`typesLoading`・`typesFailed`）も、この型で`DocumentRegisterForm`へ渡る
- 要求が1本になったため、二重に取得したときの到着順（失敗の応答で成功済みの一覧を空にしないこと）を考慮する必要がなくなった。そのテストは、応答を待つ間は要求を重ねないことを確かめるテストに置き換えた
- テスト
  - `tests/mediator-document.test.ts`: 失敗（error応答・例外）で`typesFailed`が立つ。再試行で取得し直し、取得できると戻る。応答を待つ間は、開き直しや再試行で要求を重ねない。文書の読込中に届いた失敗も受け取り、開き直すと取得し直す
  - `tests/mediator-auth.test.ts`: ログイン直後の取得失敗で`typesFailed`が立つ
  - `tests/document-register-form.test.ts`: 失敗の表示と`retryDocumentTypes`のbubble、応答待ちの`loading`、取得後のフォーカスの移動（別の入力欄にあるフォーカスは動かさない）
- ドキュメント: `docs/architecture/viewer.md`（文書表示の節）と`docs/viewer/display.md`（「文書を登録」タブ）に、失敗の表示と再試行を追記した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

1. ブラウザの開発者ツールで、`/api/v1/config/document-types`へのリクエストをブロックする。URLに`document_id`を付けずにログインすると、文書選択ダイアログが「文書を登録」タブで自動で開く。タブの先頭に「書類種別の一覧を取得できませんでした」と「再試行」ボタンが出る
2. ブロックしたまま「再試行」を押す。エラーは残り、Networkタブの要求が1件増える
3. ブロックを外し、開発者ツールで通信速度を落としてから「再試行」を押す。応答を待つ間はボタンが読込中の表示になる。その間にEnterキーを続けて押しても、Networkタブの要求は1件しか増えない
4. 応答が返ると、エラーとボタンが消え、フォーカスが書類種別の選択欄へ移る。選択欄を開くと書類種別が並ぶ

## 備考

取得には成功したが、テナントに書類種別が1件も無いときは、これまでどおり選択肢が空になるだけでエラーは出ない。原因は設定の未登録で、再試行しても解消しないため、このPRの対象外とした。

失敗の表示が出ている間に書類種別の選択欄を開くと、Vuetifyの既定の文言「No data available」が英語で出る。Vuetifyのロケールを設定していないためで、このPRでは変えていない。
