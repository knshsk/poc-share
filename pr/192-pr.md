# 概要

認証済みの画面で、原本ダウンロードの応答を待つ間に文書を切り替えたときの不具合を直す。切替前の文書のダウンロードが後から失敗すると、切替後の文書の表示中でも、画面全体が取得失敗画面（「原本を取得できませんでした」）になっていた。

## 関連Issue

Closes #186

## 変更内容

`downloadFailed`（`viewer/src/mediator/handlers/public.ts`）は、どの文書のダウンロードの失敗かを持たず、状態（`VIEWING`）だけで受け付けていた。切替後の文書が`document`状態になっていると、切替前の文書の失敗も受け付けていた。

- `downloadOriginal`は、要求した時点のスコープ（文書IDまたはtokenと、読込の世代）を`downloadFailed`に持たせる。`downloadFailed`は、スコープが表示中の文書と一致しない失敗を捨てる。判定はページ画像の応答と同じ`scopeOf`で行うため、同じ文書を開き直す前に出した要求の失敗も捨てる
- `viewer/tests/mediator-document.test.ts`にテストを2件加えた。原本の応答を保留したまま、別の文書（`doc-2`）と同じ文書（`doc-1`）をそれぞれ開く。読込が終わってから原本の取得を失敗させ、`document`状態のままでエラーが出ないことを確かめる
- `docs/architecture/viewer.md`の古い応答を捨てる説明で、同じ文書の開き直しも区別する対象に、原本ダウンロードの失敗を加えた

表示中の文書のダウンロードが失敗したときは、これまでどおり取得失敗画面になる。切替前の文書のダウンロードが切替後に成功したときも、今までと同じく原本を保存する。公開閲覧では、tokenも読込の世代も変わらないため、挙動は変わらない。

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。今回の変更を確かめる2件のテストは、`npm run test -- tests/mediator-document.test.ts -t "開く前の原本取得"`で実行できる。このテストは、Issueの再現手順と同じ順にイベントをMediatorへ送る。

切替前の文書の失敗を画面で再現するには、原本の応答を遅らせたうえで失敗させる必要がある。

1. 文書を表示し、「原本ダウンロード」で原本を保存できることを確かめる
2. ブラウザの開発者ツールで、`/api/v1/documents/{document_id}/pdf`へのリクエストをブロックする。「原本ダウンロード」を押すと、取得失敗画面（「原本を取得できませんでした」と再試行ボタン）になる

## 備考

表示中の文書のダウンロードが失敗すると取得失敗画面になり、その後の再試行・参照・登録で未保存の修正が確認なしに消える。この不具合は範囲外とし、#191 に起票した。
