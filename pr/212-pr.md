# 概要

ログインから5分を過ぎると、ViewerのAPI呼出がすべて401になる不具合を直す。Viewerは、アクセストークンを期限の60秒前に更新する。APIクライアントは、要求のたびに最新のトークンを付ける。通信断などで更新に失敗しても、次のAPI呼出で更新し直す。

## 関連Issue

Closes #209

## 変更内容

- 原因: Viewerは、OIDCのコールバックで受け取ったアクセストークンを、APIクライアントに1回だけ設定していた。`oidc-client-ts`の自動更新（`automaticSilentRenew`、既定で有効）は、期限の60秒前にrefresh tokenでトークンを更新していた。しかし、更新後のトークンはAPIクライアントへ渡っていなかった
- 更新後のトークンを渡すだけでは足りない理由: 自動更新が通信断などで1回失敗すると、次の期限前の通知が来ないまま期限を迎える。スリープから復帰した直後にネットワークがつながっていないと、Keycloakのセッションが有効でも、再読込するまで401になる。そこで、API呼出時にもトークンの期限を確かめて更新する
- APIクライアント（`api/client.ts`）: トークンを保持せず、要求のたびにトークンの取得元から得て`Authorization: Bearer`に付ける。取得元は、Mediatorがコールバックの後に`setTokenSource`で渡し、ログアウトで外す。`setAccessToken`は廃止した。公開閲覧では取得元を渡さないので、これまでどおりヘッダを付けない
- トークンの更新（`auth/oidc.ts`）: `accessToken()`を追加した。残りが60秒を超えていれば、保持しているトークンを返す。60秒以下なら、refresh tokenで更新してから新しいトークンを返す。更新に失敗したときは、保持しているトークンを返す（期限内なら要求は通る）。期限の60秒前の通知（`addAccessTokenExpiring`）でも更新し、APIを呼ばない間もKeycloakのセッションを保つ。期限前の通知とAPI呼出時の更新は同じ経路で行い、更新要求は同時に1本までにする。そのため、ライブラリの自動更新は使わない。`Session`から`accessToken`を除いた
- テスト: `tests/oidc.test.ts`では、更新の要否（期限まで余裕がある・期限直前・期限切れ）を確かめる。あわせて、更新に失敗したときの戻り値、失敗後の更新し直し、期限前の通知での更新、重なった更新が1本になることも確かめる。新規の`tests/api-client.test.ts`では、要求ごとに取得元の最新のトークンが付くことと、取得元が無いときにヘッダを付けないことを確かめる。`tests/mediator-auth.test.ts`では、コールバックで渡した取得元が、呼ばれるたびにトークンを取り直すことを確かめる
- ドキュメント: `docs/architecture/auth.md`（ログインの流れ、アクセストークンの更新、トークンとセッションの寿命）、`docs/architecture/viewer.md`（構成図、APIクライアント）、`docs/develop-guide/auth.md`（構成メモ）を更新した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

画面では、Chromeの開発者ツールのNetworkパネルで、Keycloakのトークンエンドポイント（`token`）とAPIの要求を見る。待ち時間を含めて10分ほどかかる。手順の時刻は、アクセストークンの寿命がKeycloakの既定値の300秒であることを前提にしている（realm定義では寿命を指定していない）。

1. Networkパネルを開いたまま、ログインして文書を開く
2. ログインから4分ほど経つと、`token`への要求が1件出る。Payloadの`grant_type`は`refresh_token`で、応答は200である
3. ログインから5分を過ぎたら、「原本ダウンロード」を押す。PDFを保存でき、`pdf`の要求は200になる。要求ヘッダの`Authorization`は、ログイン直後の要求と異なる
4. 更新の失敗からの回復を確かめる。2回目の更新（ログインから8分ほど）の少し前に、Networkパネルのスロットリングを「Offline」にする。`token`への要求が失敗したら、「No throttling」に戻す。ログインから9分を過ぎ、トークンの期限が切れてから「原本ダウンロード」を押す。`token`への要求が1件出た後に`pdf`の要求が出て、200になる

## 備考

Keycloakのセッション自体が切れた後は、これまでどおり操作ごとの失敗を表示する。Keycloakの既定値では、ログインから10時間を過ぎたときと、最後のトークンの更新から30分を過ぎたときにセッションが切れる。タブを開いている間は約4分ごとに更新するので、後者はスリープなどで更新が止まったときに起きる。APIへの要求では、セッションは延びない。Viewerは期限の60秒前に更新するため、Keycloakでアクセストークンの寿命を60秒以下にすると、更新が止まらなくなる。使用済みのrefresh tokenを失効させる設定（Revoke Refresh Token）は変更していない。
