# 概要

読込中・IDP実行中・確定中は文書選択ダイアログを開けないので、その間はアプリバーの文書タイトルを押せない表示にする。押せないことは、スクリーンリーダーにも伝える。

## 関連Issue

Closes #187

## 変更内容

これまでは、読込中・IDP実行中・確定中に文書タイトルを押しても、何も起きなかった。Mediatorがこの間の`openDocumentPicker`を捨てるためである。一方で`AppHeader`は状態を受け取っていないので、文書タイトルは押せる見た目のままだった。押せないことは、スクリーンリーダーにも伝わらなかった。

- ViewModel: `HeaderVm`に`pickable`を足した。Mediatorが文書選択ダイアログの開閉を受ける状態（`empty` / `document` / `documentError`）のときだけtrueになる。受け付ける状態の一覧`PICKABLE`は、`handlers/document.ts`から`model.ts`へ移した。Mediatorの裁定と`pickable`は、この一覧から決まる
- 文書タイトルの表示: `pickable`がfalseの間は`aria-disabled="true"`を付け、Vuetifyの無効なテキストボタンと同じ不透明度0.26で表示する。ポインタの操作は受けないので、ホバーしても表示は変わらない。フォーカス中にEnterを押したときの波紋も出さない。押下は今までどおりMediatorが捨てる
- `disabled`属性は使っていない。参照でダイアログを閉じた時点で読込は始まっており、閉じた後のフォーカスは読込中の文書タイトルへ戻るためである。`disabled`属性のボタンはフォーカスを受けられないので、フォーカスが`body`へ移ってしまう
- テスト
  - `tests/mediator-document.test.ts`: 8つの状態それぞれで、`header.pickable`とダイアログを開けるかどうかが一致する。ダイアログを開かない状態を確かめる既存のテストに統合した
  - `tests/app-header.test.ts`: 押せない間は文書タイトルが`aria-disabled="true"`になり、フォーカスは受ける。押せる間は`aria-disabled="false"`になる
- ドキュメント: `docs/viewer/display.md`に押せない間の文書タイトルの表示を、`docs/architecture/viewer.md`に`vm.header.pickable`を追記した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

1. 文書を表示し、ブラウザの開発者ツールで通信速度を落とす
2. Tabキーで文書タイトルにフォーカスを移し、Enterでダイアログを開く。「文書IDで参照」の入力欄に別の文書IDを入れ、Enterで参照する
3. 読込中（スピナーの表示中）に、次のことを確かめる
   - 文書タイトルが薄く表示され、ホバーしても表示が変わらない。押してもダイアログは開かない
   - フォーカスの枠は文書タイトルに残る。Enterを押してもダイアログは開かず、波紋も出ない
   - 開発者ツールのElementsパネルで、文書タイトルの`<button>`に`aria-disabled="true"`が付き、`disabled`属性は付いていない
4. 読込が終わると、文書タイトルは元の表示に戻る。押すとダイアログが開く

IDP実行中と確定中も同じ表示になる。IDP実行は実際のDocument Intelligenceを呼ぶので、画面では読込中で確かめる。

## 備考

「文書を開く」ボタン（アプリバー・空状態）は変えていない。ダイアログを開けない状態でこのボタンが出るのは登録の送信中だけで、そのときは文書選択ダイアログに覆われて押せないためである。

波紋は、`v-btn`の`ripple`プロップを切り替えるのではなく、CSSで隠している。Vuetify 4.1.11のrippleディレクティブは、無効にしてもkeydownのリスナーを外さない。そのため押せない間にEnterを押すと、次に出るはずの波紋が1回出なくなる。
