# 概要

文書ID未指定時の開始ダイアログを「文書を登録」「文書IDで参照」の2タブ構成にし、PDF 登録をドロップゾーン（ドラッグ＆ドロップ／クリックで OS のファイル選択）に変更する。

## 関連Issue

Closes #153

## 変更内容

- `StartDialog.vue` を新設し、`DocumentView.vue` の開始ダイアログ（選択画面 → 閲覧 / 新規登録の2段構成）を置き換える。初期表示は「文書を登録」タブ。タブアイコンは phosphor の `file-arrow-up` / `file-magnifying-glass`
- `DocumentRegisterForm.vue`: 項目順を 書類種別 → 文書ID → PDF に変更。PDF は Vuetify `v-file-upload`（`file-dashed` アイコン）で指定し、`filter-by-type` で PDF 以外のドロップを拒否。選択後は `inset-file-list` でゾーン内にファイル名・サイズ・変更・解除を表示し、ダイアログ高さを変えない
- 登録／参照ボタンは必須入力が揃うまで無効化。参照タブ切替時は文書ID入力欄へフォーカス。両タブの高さを揃え、切替でダイアログ高さが変わらない
- テスト: `start-dialog.test.ts` 新設、登録フォーム・DocumentView のテストを更新
- docs: `docs/viewer/display.md`「文書ID未指定時の開始画面」、`docs/architecture/viewer.md` の構成図・フローを更新

## 動作確認方法

1. ローカルスタック（postgres / keycloak / api / viewer）を起動し、`document_id` なしで Viewer を開く
2. 「文書を登録」タブが初期表示され、書類種別・文書ID・PDF ドロップゾーン・登録ボタンの順で並ぶことを確認
3. ドロップゾーンへ PDF をドラッグ＆ドロップ、またはクリックして OS のファイル選択から指定できること。PDF 以外はドロップしても受け付けないこと。3 項目が揃うまで登録ボタンが無効なこと
4. 登録すると登録した文書が表示されること（既存 API `POST /api/v1/documents`）
5. 「文書IDで参照」タブへ切り替えると入力欄にフォーカスが当たり、入力後に参照（または Enter）で文書が表示されること

## 備考

ヘッドレス Chromium（Keycloak `testuser` ログイン）で 3 状態（登録タブ初期 / 入力後 / 参照タブ）の表示を確認済み。
