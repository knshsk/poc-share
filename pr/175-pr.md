# 概要

Viewer の全画面で文字を 14px 以上にし、WCAG 2.2 AA の 1.4.3（文字のコントラスト 4.5:1）と 1.4.11（入力欄の枠・表の罫線 3:1）を満たすようにする。WCAG 2.2 には文字サイズの下限が無いため、下限はデジタル庁デザインシステムの基準（14px は領域的な制約がある場合のみ、14px 未満は原則不許容）に拠る。右ペインとキャンバスの境界、キャンバスの読取矩形の枠は 1.4.11 の対象外として据え置く（ADR-0024）。

## 関連Issue

Closes #174

## 変更内容

- 14px 未満の文字を 14px にする
  - `text-body-small`（12px）18 箇所を `text-body-medium`（14px）に、13px の指定（表のセル・候補値・発行 URL）を 14px に、`size="x-small"`（10px）のチップを `small` にする
  - 14px 化に合わせて、キー項目・候補値の状態列を 84px → 96px（「⚠ 要確認 52%」が 1 行に収まる幅）、表のセルと空行のボタンの左右余白を 6px → 4px にする（右ペイン 528px で注文書の 6 列の表が切れない）
- Vuetify の部品が内部で持つ小さい文字・薄い色を、新規の `viewer/src/assets/vuetify-overrides.css` で上書きする。Vuetify 4 のカスケードレイヤー `vuetify-overrides` に入れ、`plugins/vuetify.ts` で `vuetify/styles` の直後に import する（部品の規則には勝ち、ユーティリティクラスには負ける）
  - 入力欄の浮動ラベル: 12px → 14px
  - `size="small"` のボタン・チップ: 文字 12px → 14px（高さは据え置き）
  - プレースホルダ: 透明度 0.38 → 0.85。ラベルが無い欄と入力中の欄だけに当て、ラベル付きの未入力の欄でプレースホルダを隠す既定の挙動は保つ
  - 入力欄の枠: 透明度 0.38 → 0.64。ホバー・フォーカス・エラーの欄は Vuetify の濃さのまま
- テーマの状態色を、色相を変えずに明度だけ下げる（primary `#0F6CBD`→`#0E65B0`、warning `#9A6700`→`#885B00`、error `#D13438`→`#BC2A2E`、success `#107C10`→`#0F730F`）。白地・自色の淡色地（tonal のチップ・通知・ボタン）・選択行の灰色地のいずれでも、ホバーが重なった状態を含めて文字 4.5:1 以上になる。Vuetify が補助の文字に掛ける透明度（`medium-emphasis-opacity`）を 0.60 → 0.78 にする。起動スプラッシュの弧の色も primary に合わせる
- 箇所ごとのコントラスト
  - 表の罫線を入力欄の枠と同じ濃さ（`rgba(on-surface, 0.56)`）にする。表のセルは枠の無い入力欄で、罫線がその境界を兼ねるため
  - 実行履歴・閲覧URL 一覧の副題は、Vuetify が副題に掛ける透明度をやめて secondary 色にする（副題の中の「成功 / 失敗」の色が薄まらない）
  - ヘッダーの文書タイトルボタンは、メニューを開いている間の活性化オーバーレイを出さない（種別チップの淡色地に重なり、チップの文字が 3.6:1 になるため。開いたメニューそのものが状態を示す）
- 再発防止のテスト
  - `typography-classes.test.ts`: 14px 未満のタイポグラフィクラス（`text-body-small` / `text-label-small` / `text-label-medium`）・`size="x-small"`・14px 未満の `font-size` を `src/` から検出する。上書きの 5 規則が `@layer vuetify-overrides` の中にあること、`vuetify/styles` より後に import されていること、`main.css` に書かれていないことを検査する
  - `vuetify-plugin.test.ts`: 文字色に使うテーマ色と medium-emphasis の文字のコントラスト比を WCAG の式で計算し、白地・淡色地・選択行の地（ホバー時を含む）で 4.5:1 以上であることを検査する
- ドキュメント: ADR-0024（基準・対象外とその理由・実現方法・影響）、`viewer/README.md` のスタイル節、`docs/viewer/result-panel.md`（表の文字と罫線、列幅、アクセシビリティ節）、`docs/viewer/display.md`（アプリバー）、`docs/architecture/viewer.md`（ADR の導線）

## 動作確認方法

1920×1080・表示倍率 100%・Chromium で、次の 11 の画面状態の文字と非テキストを計測した: ログイン、文書画面（読取結果・下書きあり・実行履歴）、ツールチップ、文書切替メニュー、ユーザーメニュー、破棄確認ダイアログ、開始ダイアログ（登録・参照）、取得失敗のエラー画面。文字は計算後の文字サイズ・色・祖先の透明度と、画面上の背景色からコントラスト比を出した。

- 修正前: 14px 未満の文字 27 種、文字のコントラスト不足 7 件（最小はプレースホルダ「（値なし）」1.82:1）、入力欄の枠 2.01:1、表の罫線 1.32:1
- 修正後: 14px 未満の文字 0、文字のコントラスト不足 0（無効状態のボタンは WCAG の例外）、入力欄の枠 3.69:1、表の罫線 3.74:1。3:1 未満は対象外とした右ペインの境界（1.31:1）とキャンバスの読取矩形の枠（2.04:1）だけ
- ホバー時: 実行履歴の選択行にホバーしたときの「成功」4.62:1・副題 4.74:1、ホバー中の文書タイトルボタンの種別チップ 4.65:1。メニューを開いている間の種別チップ 4.82:1
- レイアウト: 右ペイン 528px でキー項目の状態列のはみ出し 0、注文書の 6 列の表のセルの切れ 0。最小幅 400px でも状態列のはみ出し 0（表は従来どおり、最小幅を割ると表の中で横スクロールする）
- Vuetify の既定の挙動: 入力欄の枠はホバーで 0.87、フォーカスで 1（2px）のまま。ラベル付きの未入力の欄ではプレースホルダが出ず、入力中は出る。浮動ラベルは 14px で、枠の切り欠きもラベルの幅に合う
- 本番ビルドの CSS で、カスケードレイヤーの登録順が `app-reset` → `vuetify-core` → `vuetify-components` → `vuetify-overrides` → `vuetify-utilities` であること
- `npm run test`（35 ファイル・320 件）・`npm run build`・`uv run pytest`（269 件）・`pre-commit run --all-files` が通る
