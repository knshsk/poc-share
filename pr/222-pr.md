# 概要

シードの文書種別`purchase_order`（注文書）・`quotation`（見積書）の読取エンジンをContent Understanding（CU）にし、明細を`LineItems`で返す。これまでのDIの種別は、`purchase_order_di`・`quotation_di`の種別コードで残す。ヘッダ項目のキーはDIの種別と同じなので、外部システムが`fields.<キー>`でヘッダ項目を読む方法は変わらない。

このPRは統合ブランチ`feature/213-engine-neutral-extraction`に向ける。

## 関連Issue

Closes #221

## 変更内容

- マイグレーション`c4f8a2e6d9b1`を追加した。対象は`tenant_id`が`default`の種別だけである
  - DIの`purchase_order`・`quotation`を、`purchase_order_di`（表示名「注文書（DI）」）・`quotation_di`（表示名「見積書（DI）」）に改名する。パターン・閲覧URL発行可否は変えない。項目は、見積書に版数を足すほかは変えない。参照する文書の`document_type`も書き換える
  - CUの`purchase_order`（閲覧URL発行不可）・`quotation`（閲覧URL発行可）を追加する。ヘッダ項目は、DIの種別と同じキー・ラベル・型・表示有無とし、英語の説明を付ける。明細はarray型の`LineItems`で、プロパティは`ItemCode`・`ItemName`・`Quantity`・`UnitName`・`UnitPrice`・`LineAmount`とする。パターンは登録番号（`TCode`）とする
  - 見積書の2種別（`quotation`・`quotation_di`）に、版数`RevisionNumber`（string型）を加えた。帳票の版数は「第2版」のように書かれ、number型の正規化規則では数値にできないためである。CUとDIでヘッダ項目のキーが同じという方針は保つ
  - 見積書の`SenderCompanyName`は、キー名どおり見積書の発行元を指すように説明を書いた
  - downgradeは、CUの種別を参照する文書があれば止まる。無ければCUの2種別を消し、改名と文書の書き換えを戻す
  - DIの種別がすでにCUに変えられていた場合は、CUの種別の追加が一意制約に反するため、マイグレーション全体が取り消される
- テスト: マイグレーションのテストに次の確認を追加した
  - 改名と文書の書き換え
  - CUの種別の追加。設定APIのボディとして受け付けられること、説明がすべて英語であることを含む
  - ほかのテナントの種別と文書が変わらないこと
  - downgradeで元に戻ること、CUの種別の文書があると止まること
  - `conftest.py`のテスト用の種別はDIのまま残し、コメントを直した
- ドキュメント
  - `docs/data-model/document-type-configs.md`: シードデータを4種別にし、版数の型、明細のプロパティ、説明の所在を書いた
  - `docs/develop-guide/api.md`: シードの2種別をローカルでIDP実行するには、CUの接続設定が要ることを書いた
  - ADR-0029: シードのエンジンをCUにした決定と理由を追記した

## 動作確認方法

1. `cd api && uv run pytest tests/test_migrations.py`を実行し、すべて通ることを確かめる
2. ローカルのDBで`uv run alembic upgrade head`を実行する。`GET /api/v1/config/document-types`が4種別を返し、`purchase_order`・`quotation`の`engine`が`azure-cu`で、`fields`の最後の項目が`LineItems`であることを確かめる。`purchase_order_di`・`quotation_di`の`fields`は、適用前の`purchase_order`・`quotation`と同じで、`quotation_di`だけ末尾に`RevisionNumber`が加わる
3. 適用前に`purchase_order`・`quotation`だった文書の`documents.document_type`が、`purchase_order_di`・`quotation_di`になっていることを確かめる
4. `uv run alembic downgrade e8c3a7d5f1b2`で、元の2種別に戻ることを確かめる。CUの`purchase_order`で文書を登録してからdowngradeすると、例外で止まる

IDP実行はCUの課金が発生するため、確認に含めない。

## 備考

- CUの種別では、`layout_tables`が空配列になり、明細は`fields.LineItems.items`で返る。外部システムが`fields`の全キーを、どれも`normalized_value`を持つ前提で処理している場合は、`LineItems`の値を読めない。キー名を指定してヘッダ項目を読む場合は影響しない
- CUに渡す説明は英語で書いた
