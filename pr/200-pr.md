# 概要

文書登録APIは、content-typeと先頭の`%PDF`だけでPDFかを判定していた。そのため、先頭だけが`%PDF`の壊れたファイルも登録できていた（201）。登録した文書はページ寸法の取得が500になり、Viewerで表示できなかった。壊れた文書は文書IDを使ったまま残るので、同じ文書IDに正しいPDFを登録し直すと409になっていた。登録の時点でPDFを開いて確かめ、開けなければ422で拒否するように直した。

## 関連Issue

Closes #189

## 変更内容

- `api/app/routers/documents.py`: 415の判定の後に、ページ寸法の取得（`PdfRenderer.get_page_sizes`）と同じ処理でPDFを開く。開けなければ422 `invalid-pdf`を返し、`detail`は`Failed to open PDF (corrupted or password-protected)`とする。DBの照会とBlobの保存より前に止めるので、拒否したファイルは文書IDを使わない。ページ寸法の取得は、Viewerが文書を開くときに最初に呼ぶ処理である。登録できたPDFは、この処理で失敗しない
  - 壊れたPDFのほか、閲覧パスワード付きのPDFも422になる。権限パスワードだけを設定したPDFは開けるので、登録できる
- `api/app/services/pdf_render.py`: `PdfiumRenderer`の2つのメソッドは、PDFを開いて閉じる処理と`PdfiumError`の変換を個別に書いていた。これをコンテキストマネージャ`_opened`にまとめ、ページ寸法の取得中に起きた`PdfiumError`も`PdfProcessingError`に変換するようにした。ページツリーのページ数が実際より多いPDFは、開けてもページ寸法を取れない。このPDFのページ寸法の取得は、未捕捉の例外として500 `internal-error`になっていた。変換後は、このPDFの登録が422になる。登録済みの文書なら、`GET .../pages`と公開閲覧の`/view/{token}/pages`が500 `pdf-processing-failed`を返す
- 対象外
  - この修正より前に登録された壊れた文書は、そのまま残る。要件VW-08で、誤登録の取消・差替はPoCでは設けないためである。必要なら、DBの行とBlobを手作業で削除する
  - Viewerは変更していない。登録エラーの英語の文言は #198 で扱う
- テスト
  - `tests/conftest.py`: 白紙ページのPDFを作る`make_pdf`と、`pdf_bytes`フィクスチャを追加した。`test_viewer_api.py`・`test_view_url.py`・`test_view_events.py`に重複していたPDF生成のフィクスチャを、これにまとめた
  - `tests/test_documents_api.py`・`tests/test_tenant_isolation.py`・`tests/test_document_type_configs_api.py`: 登録に使っていた偽のPDF（`b"%PDF-1.7 minimal test pdf content"`など）を、実際のPDFに置き換えた
  - `tests/test_documents_api.py`: 開けないPDF2種（先頭だけが`%PDF`のファイル、ページ数が不整合なPDF）が422 `invalid-pdf`になり、Blobに保存しないこと。続けて同じ文書IDに正しいPDFを登録すると、201になること（Issueの再現手順）
  - `tests/test_viewer_api.py`: 壊れたPDFのページ寸法が500になるテストは、壊れたPDFを登録できなくなったので形を変えた。正しいPDFを登録した後に、Blobの中身を壊れたPDFに差し替えて再現する
- ドキュメント: `docs/api/README.md`（エラーコード一覧）・`docs/architecture/api.md`・`docs/architecture/overview.md`・`docs/viewer/display.md`を更新し、ADR-0017の台帳（v1内で適用した破壊的変更）に追記した

## 動作確認方法

自動テストは、`api/`で`uv run pytest`を実行する。

画面では、Issueの再現手順で確かめる。

1. 先頭だけがPDFのファイルを作る（`printf '%%PDF-1.4\nbroken\n' > broken.pdf`）
2. Viewerの文書選択ダイアログの「文書を登録」で、このファイルを任意の文書IDで登録する。ダイアログに`Failed to open PDF (corrupted or password-protected)`が表示され、文書は登録されない
3. 同じ文書IDで、正しいPDF（`samples/quote-001.pdf`など）を登録する。登録に成功し、文書が表示される

APIでは、認証済みのアクセストークンを`$TOKEN`に入れ、手順1のファイルを登録する。422が返り、`type`は`/errors/invalid-pdf`になる。

```bash
curl -s -X POST http://localhost:8000/api/v1/documents -H "Authorization: Bearer $TOKEN" -F document_id=invalid-pdf-check-1 -F document_type=quotation -F 'file=@broken.pdf;type=application/pdf'
```

## 備考

閲覧パスワード付きのPDFは、自動テストに含めていない。テスト用のPDFを作るのに新しい依存が要るためである。PDFiumで開けないPDFと同じ経路で422になる。
