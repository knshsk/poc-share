# 概要

右ペイン「読取結果」タブのエディタを再設計する。キー項目は確信度バーをやめて状態表示（未保存 / 修正済 / 未読取 / 要確認 n% / n%）にし、表は罫線付きの表組み（空行の畳み・内容に比例した列幅・数値の右寄せ）にする。候補値は読取専用の入力欄にし、区分名を「候補値」「表」に改める。UI 是正 第2弾（親 #159）の 3 件目（最後）。

あわせて、マージ済みの #158 / #163 / #164 を Fable 5.1 で再レビューした指摘への対応を含む（後述）。

## 関連Issue

Closes #162

## 変更内容

- 純関数を追加
  - `utils/fieldStatus.ts`: 状態の判定（優先順 未保存 > 修正済 > 未読取 > 確信度。80% 未満だけ警告色の「要確認 n%」、それ以外は中立色の「n%」）
  - `utils/table.ts`: `textWidth`（半角 1 / 全角 1.7）、`columnTemplate`（列の内容幅に比例した `minmax(…ch, …fr)`）、`rowBlocks`（連続する空行の塊）、`isNumeric`
  - `utils/runs.ts`: `parseCellId`、`CORRECTION_MAX_LENGTH`、`visibleFieldKeys`
  - `utils/format.ts` の `confidenceColor` は削除
- `KeyFieldList.vue`（新規）: 行 = ラベル | 入力欄 | 状態。確信度バー・色付きの % ・欄内の鉛筆・左アクセントを廃止。未保存 = 薄い primary の塗り、キャンバスと連動中 = 2px の primary 枠。状態・読取値・ヒントは `aria-describedby` で入力欄に結び付ける
- `ResultTable.vue`（新規。`PageSvg` と同じく素の props を受ける末端部品）: CSS grid の罫線付きの表。枠なしのネイティブ `<input>`、行高 32px、ヘッダー行の見た目（編集は可能）、数値セルは右寄せ、DI のデータに無い座標は入力欄を出さない
  - 連続する空行は「空行 N 行を表示 / 隠す」ボタン（`aria-expanded`）で畳む。既定は畳む。キャンバスで畳まれた行のセルを選ぶと、その塊を開いてからフォーカスする
  - 保存済みの修正 = セル右上の三角 + `title` + `hidden` のテキスト「修正済」（`aria-describedby` で参照）。下書きがあれば下書きの表示を優先
  - 表ごとに `role="group"` + 見出しの `aria-labelledby`（複数の表の同名セル「2行1列」を区別できる）
  - 列幅は CSS 変数 `--tbl-columns` で渡す（528px の右ペインで 6 列の表が横スクロールなしに収まる）
- `ResultEditor.vue`: 3 区分のアコーディオン（キー項目 / 候補値 / 表）と `focusRequest` の監視だけに縮小（約 495 行 → 約 200 行）。候補値はチップから読取専用の入力欄に変更（複数の値は縦に並べる）
- ドキュメント: `docs/viewer/result-panel.md`、`docs/viewer/display.md`、`docs/architecture/viewer.md`、`viewer/README.md`

変えていないもの: `EditorVm` の型、Mediator のイベント（`fieldInput` / `cellInput` / `targetFocus`）、`WorkPanel` からの受け渡し（`run_id` を key に再マウント）、修正・下書き・確定の挙動、キャンバス側のオーバーレイ ID（`field:key` / `cell:t:r:c`）。

### マージ済み 3 件の再レビューへの対応

マージ後の 3 件を再レビューした結果（Critical 0 件）と、このブランチで行った対応。

- **#164（右ペイン幅）**: 境界に触れていなくても、ウィンドウを縮めて戻すと既定幅 528px が失われる不具合を修正。利用者が決めた幅（状態）は縮めず、実際に表示される幅（状態と上限の小さいほう）を `aria-valuenow` とキー操作の基準にした。広げ直すと元の幅に戻る。あわせて、主ボタン以外ではドラッグを始めない、矢印キーは修飾キーなしのときだけ（Alt+←/→ のブラウザの戻る / 進むを奪わない）、forced-colors 用の透明 outline
- **#164（表示中）**: 幅が足りないとき日時から先に削れていたのを、区分・修正者だけを省略し日時とチップは必ず残すように変更。実行履歴の行のサブタイトルを 12px にして階層を戻した
- **#163（ヘッダー）**: GUID の文書 ID + 長いファイル名 + メール形式のユーザー名で、幅 1280px からロゴが 2 行に折れ、1110px 以下でユーザーメニューが画面外へ切れていた（実測）。文書 ID を優先して縮め、ファイル名も省略記号で切り、ロゴとユーザーメニューは縮めないようにした。タイトルボタンに視覚的に隠した「文書を切り替える」を追加、空文字のファイル名は null 扱い
- **#158（第1弾）**: Vuetify 4 の reset は `<p>` の margin を 0 にしないため、`mt-1` / `mb-2` が既定の `margin-block: 1em` に相殺されていた。`main.css` に最下位レイヤーの `@layer app-reset { p { margin: 0 } }` を追加（レイヤー無しだと `mt-*` に勝ってしまう。テストで guard）。等幅フォントのスタックに `IBM Plex Sans JP` を追加（日本語を含む正規化値のヒント・候補値が環境依存の和文フォントに落ちていた）。旧タイポグラフィクラスの検出を拡張（`text-button`・レスポンシブ形・MD3 名の typo）。失効確認ダイアログのアクセシブルネーム、`<html lang="ja">`
- **既存の挙動の改善**: 結果のある文書を開いたとき、一覧の応答から最初の詳細の応答までの間「実行結果がありません」が一瞬出ていたのを、スケルトンのままにした（`WorkPanelVm.loadingRuns` の条件のみ。型の変更なし）
- docs の不一致を修正（IDP 実行失敗時のサーバ側の失敗実行、縦積みは「960px 以下」）

## 動作確認方法

ローカル環境で testuser ログイン後、文書を開いて「読取結果」タブを操作する。ヘッドレス Chromium での確認結果（1440×900、右ペイン既定 528px。IDP 実行 API への POST は遮断して実施）:

- 状態表示: 要確認 52% / 91% / 未読取 / 修正済 / 未保存。確信度バーなし。キー項目の行高 44px（読取値の補足つきは 64px）
- 表: 2 件とも横スクロールなし（504/504px）、セル行高 32px、数値セルは右寄せ、ヘッダー行は塗り
- 空行 5 行が「空行 5 行を表示」に畳まれる。キャンバスで畳まれた行のセルの矩形をクリックすると、塊が開いてそのセルにフォーカスが移る
- セル / キー項目の編集で塗り + 「未保存」+「変更 n件」、破棄で元に戻る
- 候補値は読取専用の入力欄、区分名は「候補値」「表」

再レビュー対応分（同じ環境）:

- 展開した空行の中ほど / 先頭の行に 1 文字ずつ入力しても、フォーカスと入力が保たれる。両隣の空行を隠して入力を空へ戻しても行が消えず、下書きは 0 件に戻る
- 表の区分を畳んだ状態でキャンバスの空セルの矩形をクリック → 区分が開き、空行が展開され、そのセルにフォーカス。表の下のほうのセルでも、展開後に表示範囲へ入る（高さ 600px の画面で確認）
- 12 列の表（応答を差し替えて確認）で、横スクロール部分まで上の罫線が届く。6 列の表は従来どおり横スクロールなし
- 右ペイン: 未操作で 1440 → 800 → 1440px と変えても 528px のまま。704px にしてから 1000px へ縮めると 674px（`aria-valuenow` も 674、→キーが 1 回目から効く）。Alt+←・右ボタンのドラッグでは幅が変わらない
- ヘッダー: GUID の ID + 約 100 文字のファイル名で、testuser・メール形式のユーザー名とも 1440 / 1280 / 1110 / 1024 / 960px でユーザーメニューが切れず、ロゴは 1 行のまま
- 右ペイン 400px + 長い修正者名でも「表示中」の日時とチップが見える。実行履歴の行は 14px / 12px
- `<p>` の間隔: ログイン（下 24px）、文書エラー（16px / 16px）、実行 0 件の案内（4px）、閲覧URL 発行直後の注意書き（12px。発行の POST は差し替えて確認）。本番ビルドの CSS でも `app-reset` レイヤーが Vuetify のレイヤーより前
- #160 / #161 の確認スクリプトも再実行し、すべて通過

## 備考

- 実装後に全体最終レビューと over-engineering レビュー（ponytail-review）を実施。最終レビューの Important 4 件はこのブランチで修正し、修正範囲を再レビュー済み
  - 展開した空行のセルに 1 文字入力するとフォーカスが消える（行が塊ごとの keyed Fragment の子で、入力で塊が分かれると `<input>` が作り直されていた。承認済みモックにも同じ欠陥）→ 行を行番号キーで 1 列に並べた
  - 表の区分を畳むと、キャンバスで畳まれた空行のセルを選んでも反応しない（Vuetify 4 は畳んだ区分の中身を unmount する）→ 表の区分だけ `eager`
  - 空行ボタンのキーボードフォーカスが見えない → `:focus-visible` の outline
  - 再レビューの Minor と、その後の実測で見つけた 1 件（畳んでいた区分を開いた直後は展開トランジションの途中で `scrollIntoView` が走り、フォーカス先のセルが画面外に残る）→ 区分を開いた場合だけ、区分の本文自身の `transitionend` でもう一度表示範囲へ入れる。入力した行は展開済みとして記録し、入力中の行が畳まれる残りの経路も塞いだ
  - いずれも修正前に実ブラウザで再現し、修正後に解消を確認。jsdom の単体テストでは Transition の stub が隠していたため、実トランジションの回帰テストを追加
- 数値セルの右寄せは元の読取値で判定する（下書きで判定すると入力中に寄せが反転するため。モックと同じ）
- 見送り（必要になったら対応）
  - 「過去の結果」などの x-small・tonal チップのコントラスト（計算上 4.17:1）: 配色は今回の対象外
  - 境界の Home / End キー（APG では任意）、当たり判定 6px、マルチポインタ時の `lostpointercapture` の照合
  - 結合セル（`row_span` / `column_span` > 1）は従来どおり起点セルのみ描画。実データでの見え方は未確認
- 別 Issue にすべき既存の不具合（再レビューで発見。いずれも今回の差分外）
  - API: `_original_filename` が制御文字を落とさないため、細工したリクエストの `filename="a\x00b.pdf"` で 500 になり、blob だけが残る（blob の保存が DB の commit より前）
  - Viewer: DI の複数行セル（`content` に改行）は `<input>` が改行を除去して連結表示し、確定すると改行が失われる（旧実装も同じ）
- これで親 #159 の sub-issue（#160 / #161 / #162）はすべて完了
