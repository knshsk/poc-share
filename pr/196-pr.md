# 概要

次の3つのダイアログで、閉じた後のフォーカスが`body`に残らないようにする。対象は、文書選択ダイアログ・未保存の変更の破棄の確認・閲覧URLの失効の確認である。閉じた後は、開く前にフォーカスのあった要素へ戻す。戻せないときは、ダイアログごとに決めた要素へ移す。

## 関連Issue

Closes #188

## 変更内容

3つのダイアログは、`v-dialog`をactivatorなしで開く。このため、閉じてもVuetifyはフォーカスを戻さない。文書選択ダイアログは、開く前の要素へ戻す処理を持っていた。ただし、自動で開いたときと開く前の要素が画面から消えたときは、フォーカスが`body`に残っていた。確認ダイアログの2つには、戻す処理が無かった。

- 共通の処理: `viewer/src/utils/returnFocus.ts`に`useReturnFocus`を足し、3つのダイアログで使う。開いた時点でフォーカスのあった要素を覚え、閉じた時点でそこへ戻す。戻せないときは、ダイアログごとの移し先へ移す。文書選択ダイアログの既存の処理（`returnFocus`・`onAfterLeave`）は、`useReturnFocus`に置き換えた
- 戻せたかどうかの判定: 戻し先に実際にフォーカスが当たったかどうかを見る。画面から消えた要素・隠れた要素・無効な要素を、1つの条件で扱える。判定は、閉じる操作で変わった後の描画を待ってから行う。たとえば空状態の「文書を開く」から参照すると、ダイアログを閉じるのと同じ描画の更新で、このボタンが消える。描画を待たずに判定すると、消える前のボタンへ戻してしまう
- 移し先
  - 文書選択ダイアログ: アプリバーの文書タイトル（文書が無いときは「文書を開く」）。2つのボタンに共通の`id="document-picker-entry"`を付けた
  - 未保存の変更の破棄の確認: 右ペインで選択中のタブ。実行履歴の行から開いた場合は、確認を出す前に読取結果タブへ切り替えるので、行が隠れている。「破棄して続行」でIDP実行を進めた場合は、実行中のIDP実行ボタンが無効になる。どちらも開く前の要素へは戻せない
  - 閲覧URLの失効の確認: キャンセルで閉じたときは、行の「失効させる」へ戻す。失効を確定したときは「閲覧URL発行」へ移す。確定した行の「失効させる」は、一覧の再取得で消えるためである。戻した後に消えると、フォーカスはまた`body`に残る
- 開いたまま部品ごと消えた場合: 文書選択ダイアログから登録し、破棄の確認で続行すると、確認ダイアログは右ペインごと消える。開閉の値が変わらないまま部品が消えるので、部品が消える時点で開く前の要素（送信中の登録ボタン）へ戻す
- テスト
  - `tests/return-focus.test.ts`（新規）: 開く前の要素へ戻す。開いた時点でフォーカスが無い・要素が消えた・要素が無効・覚えた要素を捨てた、のいずれかなら移し先へ移す。開いたまま部品が消えたときは戻す。閉じたままならフォーカスを動かさない
  - `tests/root.test.ts`: 自動で開いたダイアログを閉じると、「文書を開く」へ移る。アプリバーと空状態の「文書を開く」から参照すると、文書タイトルへ移る
  - `tests/work-panel.test.ts`: 破棄の確認を閉じたとき、戻せなければ選択中のタブへ移る
  - `tests/view-url-panel.test.ts`: 失効の確認をキャンセルすると「失効させる」へ戻り、確定すると「閲覧URL発行」へ移る
  - `tests/document-picker.test.ts`: フォーカスを戻すテスト2件を、`tests/return-focus.test.ts`へ移した
- ドキュメント: 閉じた後のフォーカスを、`docs/viewer/display.md`（文書選択）・`docs/viewer/result-panel.md`（破棄の確認）・`docs/architecture/viewer.md`（失効の確認）に追記した。`docs/architecture/viewer.md`の`utils/`の表に、`returnFocus.ts`を足した

## 動作確認方法

自動テストは、`viewer/`で`npm run test`を実行する。

画面では、各手順の後にTabキーを押し、フォーカスがページの先頭へ移らないことも確かめる。フォーカスのある要素は、開発者ツールのコンソールで`document.activeElement`を評価しても分かる。

文書選択ダイアログ

1. URLに`document_id`を付けずにログインする（ダイアログが自動で開く）。Escで閉じると、アプリバーの「文書を開く」にフォーカスが移る
2. 「文書を開く」から開き、「文書IDで参照」で文書を参照する。閉じた後は、置き換わった文書タイトルにフォーカスが移る
3. 文書タイトルから開き、Escで閉じる。フォーカスは文書タイトルへ戻る

未保存の変更の破棄の確認（実行結果のある文書で、読取結果の項目を修正しておく）

1. 実行履歴タブで別の行を押し、「キャンセル」で閉じる。フォーカスは「読取結果」タブへ移る
2. Tabキーで「IDP実行」にフォーカスを移し、Enterで確認を開く。Escで閉じると、フォーカスは「IDP実行」へ戻る。「破棄して続行」は押さない（実際のDocument Intelligenceを呼ぶため）
3. 文書タイトルから文書選択ダイアログを開き、別の文書IDで参照する。破棄の確認をEscで閉じると、フォーカスは文書選択ダイアログの入力欄へ戻る

閲覧URLの失効の確認（共有できる種別の文書の閲覧URLタブで、有効な閲覧URLが無ければ「閲覧URL発行」で発行しておく）

1. 「失効させる」から開き、Escで閉じる。フォーカスは「失効させる」へ戻る
2. 「失効させる」から開き、確認の「失効させる」で確定する。フォーカスは「閲覧URL発行」へ移る。一覧が更新されてその行の「失効させる」が消えた後も、フォーカスは「閲覧URL発行」に残る

## 備考

フォーカスを移す時点は、Vuetifyがactivatorへ戻す時点と同じく、閉じた時点（退場の演出の前）にした。これまでの文書選択ダイアログは、退場の演出が終わってから戻していた。閉じた時点で移すと、各ダイアログで`@after-leave`をつながずに済む。

戻せたかどうかは、戻し先にフォーカスが当たったかで判定し、「フォーカスが`body`に残ったか」では判定しない。閉じた時点のフォーカスはダイアログの中の要素にある。退場の演出の後も、Chromeは非表示になった要素にフォーカスを残す。

jsdomは、非表示の要素や、loading中（`tabindex="-1"`）の無効なボタンにもフォーカスを当てる。このため、「実行履歴の行が隠れた」「IDP実行ボタンが無効になった」の2つの経路は、単体テストで再現できない。`tests/work-panel.test.ts`では、開いた時点でフォーカスが無い経路を使い、選択中のタブへ移ることを確かめている。
